# 管理页面模块多选删除方案

用户应能连续勾选多个目录，一次确认删除，知道哪些目录成功、哪些因依赖被保留。点击目录名继续浏览右侧内容，勾选框独立管理待删除集合。

## 现状与改动范围

| 入口 | 代码现状 | 处理方式 |
| --- | --- | --- |
| 接口管理的模块树 | 普通模块支持累加勾选和子树影响预览。受保护的「未分类」复选框实际选择当前页接口，与模块选择互斥。 | 增加「全选普通模块」、半选、清空和数量反馈。把「选择本页未分类接口」明确放在接口列表，保留原有批量删除接口能力。 |
| 测试用例的 API、UI、AI 范围树 | 共用 TestCases.tsx。目录仅支持导航和单个删除，右侧用例列表已有批删。 | 给三个方向共用的树增加独立勾选、全选可见目录、清空和删除入口，按当前项目和方向隔离选择。 |
| 业务管理的业务域、流程 | DomainTree.tsx 已分别支持全选、批删和依赖检查。 | 回归连续勾选、全选、部分失败和切换项目；保留域与流程各自的依赖规则。 |
| 测试数据的 Fixture 树 | entity_type 是前端分组，持久化资源是 Fixture。已有勾选及 Fixture 批删。 | 分组勾选用于选择其下的条目，确认框明确显示 Fixture 数量。 |

实施时沿管理页路由核对其余入口，登记持久化目录、按字段生成的分组和资源列表。凡有独立删除入口的业务目录都纳入验收；纯筛选分组只对明确选中的成员执行已有资源操作。后台用户、项目等普通资源列表继续使用各自的批量操作。

## 选择与删除规则

1. 全选针对当前列表或搜索结果中可勾选的目录，并标明作用范围。系统节点禁选；测试目录父子可独立勾选。切换项目或测试方向时清空勾选，避免旧请求的回执修改新上下文。
2. 接口模块沿用现有子树预览，父子重复选中由后端去重。确认框展示实际影响的模块和接口数量；取消预览保留勾选。
3. 测试目录复用 dataLifecycleApi.deleteMany('test_scope', projectId, ids)。服务端已有系统目录、子节点和关联用例检查。只删除明确勾选且通过检查的目录。父子同选时先处理子节点，仍含未选子节点或用例的父节点保留。实施前验证批处理顺序，必要时在服务端为 test_scope 加入稳定的子先父后排序。
4. 确认框说明删除对象和回收站行为；请求期间防止重复提交。按回执移除成功项，失败项保留勾选并展示目录名和原因。删除当前浏览目录后回到同方向仍存在的父目录或根视图，刷新目录、统计和列表。

## 验收

- 接口管理连续勾选两个普通模块，计数从 1 增至 2；全选排除「未分类」，父子同选的影响数不重复。通过右侧表头仍可选择本页未分类接口。
- 测试用例三个方向分别验证空目录批删、父子同选、含用例目录被拒和系统目录禁选。混合提交两个空目录和一个含用例目录，预期成功 2 个、失败 1 个，失败项及用例仍可查看。
- 验证筛选后的全选范围、取消确认、项目切换，以及桌面和窄屏的勾选操作；操作后检查回收站可恢复成功项。
- 只用隔离测试项目执行删除验证。运行前端类型、lint、单测和相关 Playwright 场景；验证服务端权限、依赖和部分成功回执。交付时逐页记录实测结果。
