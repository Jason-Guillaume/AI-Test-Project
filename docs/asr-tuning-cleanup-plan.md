# ASR 清理计划：仅保留同一接口的参数效果对比

用户从控制台进入 FunASR 调优，选定一个识别接口、一批录音及对应的标准答案，运行基线和候选参数，查看每轮使用的参数、字符错误率（CER）及逐条识别结果。音频资产作为准备材料的辅助入口。实施以现有调优会话为基础。

## 五个现有入口如何处理

| 工作区入口 | 处理 | 涉及的操作 |
| --- | --- | --- |
| AI 分析与调优 | 设为 ASR 默认入口，沿用 `/console/asr/funasr` | 保留接口绑定、响应映射、单轮基线分析、自动多轮调优、会话控制、轮次与最佳结果。现有文本模型参与分析，实际识别由选定的 FunASR 接口执行。 |
| 音频资产 | 精简 | 保留导入、编辑、检查及试听录音、版本和标准答案绑定。移除创建评测、最近模型运行、跳转任务和工作台，以及对应的数据查询。 |
| 评测任务 | 下线 | 移除三模型任务向导、即时与定时批次、任务详情、旧任务重跑和失败重试。附属的单模型结果工作台和回听页随之下线。 |
| 结果对比 | 下线 | 移除三方结果列表、逐段差异复核、旧内容评审与调参建议入口。 |
| 参数实验 | 下线 | 这里的候选实验依赖旧三方对比 ID 和候选任务 ID。移除这条创建、复跑、回查流程；用户在 FunASR 调优会话中比较各轮参数。 |

## 实施顺序

1. **建立可复测的基线。** 从 [工作区导航](../frontend/src/pages/console/ASREvaluation/AsrFrame.tsx)、[调优 API 客户端](../frontend/src/features/asr-evaluation/api/funasrTuning.ts) 追到 [后端路由](../backend/app/features/asr_evaluation/router.py)。在隔离环境固定录音、答案版本和测试接口响应，记录一次基线与候选轮的参数、CER、识别调用数。查找域外调用方，尤其是模型中心、部署脚本和验收用例。代码引用只能说明仓库内依赖，上线前另核实外部 API 调用情况。
2. **切换前端入口。** 更新 [路由](../frontend/src/app/App.tsx)、[侧栏与标题](../frontend/src/app/layouts/ConsoleLayout.tsx)、工作区标签和音频页按钮。把旧 jobs、runs（含 listen）、comparisons、experiments 列表及详情书签导向调优页；旧 connections 入口继续按角色导航，普通用户的返回链接指向调优。清除仅用于旧界面的客户端方法、类型、草稿守卫和轮询。用浏览器直接打开旧详情链接并刷新，核对最终页面及网络请求。
3. **先解开共享依赖，再删服务。** [调优服务](../backend/app/features/asr_evaluation/services/funasr_tuning_service.py) 使用音频版本、Markdown 渲染、旧对比服务的 `_model_access` 和内容评审的 `list_review_models`。[调优 Worker](../backend/app/features/asr_evaluation/runtime/funasr_worker.py) 也引用模型授权、评审输入版本、请求并发控制和响应脱敏。逐项核对其余调用方，授权与模型列表优先复用已有公共实现。保留调优需要的音频 API、模型中心平台能力及应用启动的 `FunAsrTuningWorker`。分别验证有权限、授权被撤回和跨项目取数的行为。
4. **有序退役旧任务。** 发布时先关闭旧任务写入口，覆盖新建、复跑、重试、候选建议和实验触发，同时停止定时计划派发。记录启用计划、排队任务、在途外呼及状态待核实的任务。允许已提交的任务收尾，对远端结果未知的请求逐项核对，避免重复识别。确认旧队列无需再消费后，再移除专用路由、执行逻辑，以及 [Compose](../compose.yaml) 中的独立 `asr-worker`、启动命令和健康检查。调优会话自己的执行时段、暂停恢复和重试能力仍有独立用途。
5. **收尾与回退。** 更新仍介绍旧流程的操作指南、部署说明和验收脚本。历史任务、对比记录、音频和产物按原样保留，历史 Alembic 迁移继续可从空库执行。涉及旧 ORM 或存储卷时，先检查外键、迁移导入和共享文件引用。若切换后调优失败，回退应用及 Compose 版本，先核对已提交任务和计划状态，再恢复旧调度，以免补发重复任务。

## 验收条件

- **用户能完成参数对比。** 在同一项目、同一接口和同一批录音及答案版本下，用确定性测试响应产生基线与一个参数不同的候选轮。刷新后能读回两轮参数、逐条结果和 CER；可追溯最佳轮次。单轮基线仍可独立运行。记录每轮调用数，与清理前同一输入核对。
- **旧入口已退出。** 控制台从 ASR 菜单直达调优。音频页只提供材料准备操作。旧书签按上述规则跳转，访问调优及音频页均无旧任务、三方结果或最近运行查询。直接请求退役写接口、跨越旧计划触发时间，均不会创建旧任务。
- **已有数据与异常路径可验证。** 用清理前创建的录音、答案和调优会话复测。覆盖无标准答案、接口失败、会话暂停恢复及项目隔离。在隔离环境用已有旧任务验证收尾后无重复外呼，复核历史记录与产物仍在。
- **检查能重复运行。** 后端在 `backend/` 执行 `python -m pytest -q app/features/asr_evaluation/tests/test_funasr_analysis.py app/features/asr_evaluation/tests/test_funasr_tuning_synthetic.py`，按受影响依赖补跑音频、权限和迁移测试。前端在 `frontend/` 执行 `npm run typecheck`、`npm run lint`、`npm test`、`npm run build`。将旧流程专用断言替换为对应的退役验证。交付时分别列出测试替身验证和真实服务联调结果。
