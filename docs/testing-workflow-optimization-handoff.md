# 测试工作流与智能体协作优化：开发交接

编写日期：2026-10-27。本文用于交给开发 Agent 实施。先核对当前代码和工作区状态；本文中的现状是编写时观察到的情况，不代替实施前的核查。

## 一、背景和目标

当前控制台的导航混合了测试方式、测试准备工具和智能体角色：接口测试分散在接口管理、测试资产和执行页面；Web UI 自动化有专业页面；Mock 和测试数据原来与 Web UI 并列；Web UI 智能体又有独立入口。用户很难判断在哪里设计测试、准备依赖、发起智能任务和查看产物。

目标是围绕一条可追溯的用户工作流整理平台：

1. 接口测试和 Web UI 测试作为同层级的测试方式；安全测试是可覆盖接口或网页的专业测试工作区。
2. 测试数据、Fixture 和 Mock 是测试准备能力，可以供不同测试方式复用。
3. 统一任务承载目标、计划、任务内主代理、专业代理、审核、运行及产物；用户仍可直接使用原有管理页面。
4. Web UI 智能体的浏览器交互与人工审核融入任务工作流，正式用例仍在 Web UI 工作区管理。
5. 测试结果、疑似问题、缺陷和通知可以追溯，避免用户在多个页面重新输入上下文。

## 二、术语与边界

| 对象 | 含义和归属 |
| --- | --- |
| 接口测试 | 直接调用接口并验证响应、状态及业务结果。 |
| Web UI 测试 | 操作浏览器页面并验证行为和结果。 |
| Mock | 为测试模拟依赖服务或接口，不是一种与接口/UI 同层级的测试方式。 |
| 测试数据/Fixture | 准备测试输入和前置状态，可被多种测试方式使用。 |
| 全局 AI 助手 | 接收用户咨询、帮助发起或查询任务；与具体任务内主代理的会话分开。 |
| 任务主代理 | 在一次任务运行内理解目标、澄清需求、协调工作和汇总结果。 |
| UI Worker | 任务运行内按授权执行网页专业工作的代理实例；不是共享的全局可变会话。 |
| 浏览器工作区 | 提供页面观察、人工审核和证据展示的用户界面；可以独立路由，但必须明确所属任务和运行。 |

任务保存业务资源的引用、来源和必要版本信息；测试资产、执行记录、报告和缺陷仍由各业务模块管理。不要为统一任务复制第二套业务主表。不要将 GUI 入口的调整当成代理链路已经打通。

## 三、已有工作与当前限制

以下内容已在当前工作区进行过调整，实施前先核对，不要覆盖用户或其他 Agent 的未提交改动：

- 侧栏已将测试数据和 Mock 放到“测试准备”，将 Web UI 和安全测试作为“测试设计”中的专业工作区；保留原路由。Web UI 工作区可进入原有浏览器智能编写页面。
- 可从已确认 Web 用例创建 Web 任务，从安全工作区进入安全评估任务创建；任务创建读取 Web 用例时已处理分页。
- 测试资产支持根据 `caseId` 定位用例并显示关联任务。核对跨项目、Web 用例和历史运行等边界后再扩展。
- 任务的重要事件已写入发起人的站内通知，消息可进入任务。通知与任务事件在同一事务；覆盖方案待确认、完成、完成但有问题、失败、模型等待及执行结果待核对。现有实现仍需结合真实调度链路验证。
- 修复了项目环境未绑定时环境服务缺少 `not_found` 导入的问题。
- 已有 Web UI 智能体使用旧的 Agent 会话和受控浏览器会话进行交互式编写；任务内 UI Worker 主要执行已确认 Web 用例。两条链路尚不能视为已打通。
- `WEB_AGENT_SESSION` 当前已有用于安全评估输入的资源引用，不能直接视为通用 Web 智能编写已接入任务。
- 当前任务创建对 API/Web 一般要求已确认用例；同一运行不支持混合 API 与 Web 用例。支持仅凭自然语言目标开始交互式 Web 编写需要新增真实工作流，不能简单去掉校验。
- 缺陷与回归、外部通知等能力有未接入项；安全疑似问题不等于已确认缺陷。

## 四、功能需求

### 4.1 导航与资产入口

- 按用户工作内容组织入口：测试设计、测试准备、测试执行、任务与协作；项目级通知渠道归配置。当前分组已做第一步，继续检查页面标题、面包屑、快捷入口及文案是否一致。
- 用户应能找到接口、Web UI 和安全相关测试资产，理解各自归属。可用统一入口和专业工作区/筛选解决，不强制合并数据模型；不要将尚未接入的统一列表展示成已实现。
- 从测试数据、Mock 和专业测试页面明确进入对应的已有业务功能。保持原路由及旧链接可用；若重定向，保留必要参数并测试动态路径。
- 测试资产与 Web UI 工作区的跳转应定位正确项目和对象；不要让 Web 用例误用不支持 Web 步骤的通用编辑器。

### 4.2 统一任务与浏览器智能编写（核心）

支持用户在统一任务中提出网页目标，即使尚无已确认 Web 用例，也可以安全地创建“交互式 Web 编写”工作。该工作流应区别于现有“执行已确认 Web 用例”流程。

期望流程：

1. 用户选择有权访问的项目、执行环境，填写目标及必要范围；需要登录态时选择受控引用。
2. 系统创建任务和独立运行，任务主代理/规划器提出执行方案，人工批准后由任务内 UI Worker 承担网页编写工作。
3. 用户从任务详情打开浏览器工作区，能看到所属项目、任务、运行、实际代理实例、浏览器状态、目标、步骤提案和待确认事项。
4. 用户审核并确认或驳回需确认的步骤；继续遵循既有目标白名单、敏感数据脱敏、步数预算和人工确认约束。不要让代理绕过确认门禁。
5. 会话中真实执行且经接受的步骤可生成未确认的 Web 用例草稿；草稿保存在现有 Web 资产模块，必须人工审核确认后才可正式执行。
6. 任务详情可打开该会话、草稿、步骤结果及可用的截图/Trace；草稿详情能反查来源任务与具体运行。记录真实来源，不伪造旧会话属于任务内 Worker。

任务运行、代理实例、浏览器会话、对话和草稿需有服务端持久关联及权限校验：同项目、正确运行和授权主体；禁止跨任务共享可变上下文。明确任务重跑、目标变更和历史运行如何保留与查看；对重复请求、并发确认、取消和重试做幂等或明确冲突处理。

处理浏览器资源生命周期：谁拥有会话、配额与释放时机；页面刷新后恢复持久化状态；浏览器句柄或进程失效时明确提示并要求重新启动，不声称能恢复已丢失的浏览器状态。暂停、取消、会话关闭和后端重启均不能留下误导性“仍在运行”的状态。涉及迁移时根据实际 Alembic head 新建迁移。

旧浏览器智能编写路由与已有历史会话继续可访问；旧数据无真实关联时显示为独立历史会话，不编造来源。新工作流稳定并覆盖原场景后再考虑进一步收敛入口。

### 4.3 从资产发起任务及产物追溯

- 接口用例、已确认 Web 用例和安全评估应可从各自页面发起对应任务，正确预填项目、类型和所选资源；用户改变项目/类型时清除不再有效的选择，服务端重新校验。
- 任务详情区分输入引用和实际产物，使用可读名称及正确链接；测试运行、报告、用例、浏览器会话和安全结果在支持时可双向跳转。
- 链接需指向正确项目、对象和历史运行，不用任务 ID 与运行 ID 互相替代。跨项目链接应先核验权限，明确当前项目切换行为。
- 数据准备、Fixture、Mock 的引用与执行结果应尽可能从现有真实记录展示；不要通过文案推断实际使用了某个 Mock。

### 4.4 测试结果与缺陷

- 在失败的测试结果和安全疑似问题处，提供人工发起创建缺陷或关联已有缺陷；带入可安全展示的来源信息，用户确认后才写入。
- 建立可持久追溯的关系，使缺陷详情可返回来源结果/任务，来源页面可查看关联缺陷。关联和查询均执行项目权限检查；不跨项目暴露资源。
- 对重复点击、已有关联、被删除资源和无权限资源给出清楚行为。避免把敏感请求、凭据或未经脱敏的证据复制到缺陷。
- 安全 Finding 在人工确认前仍称“疑似问题”，不得自动定性为已证实漏洞。回归关联可作为后续子阶段，但如果本轮实现，必须通过真实用例与执行记录，而非只加状态字段。

### 4.5 消息与通知

- 保留站内消息和外部渠道的区别。确保方案待确认、任务完成/失败、需核对等已有通知在真实任务运行中正确触发，收件人和项目可见性准确，事务回滚不留下通知。
- 消息应跳至正确任务和运行；历史运行不能悄悄跳到另一次运行并造成误解。通知读取、已读、删除保持原有行为。
- 通知渠道页面明确当前支持的飞书渠道、启用/连通状态和发送结果。只对已接入的业务提供发送入口；缺陷外部推送没有实现时明确显示，不得假称自动发送。
- 如需新增待用户回复/步骤审核消息，确保事件有去重或一次状态变化只产生一次通知，并覆盖重试与恢复。

## 六、推荐实施顺序与验收

### P1：核对现状并修正导航与链接

验证接口、Web、安全工作区和测试准备入口；修复项目作用域、旧链接、用例详情和历史运行定位问题。验收：接口及 Web 用户都能找到自己的用例；Mock 作为准备能力被复用；旧地址仍可用。

### P2：任务内 Web 智能编写闭环

按 4.2 设计并实现后端模型/契约、调度和浏览器生命周期，再接入前端工作区与双向产物链接。验收：从无用例的网页目标创建任务，批准方案，使用真实任务内 UI 代理及受控浏览器，经人工确认生成未确认草稿，并能从任务与草稿双方追溯。

### P3：结果、缺陷与消息闭环

实现测试结果/疑似问题与缺陷的人工创建、关联及双向查询，核对已有任务站内通知；如新增通知类型，补齐接收和跳转。验收：一条真实结果可关联缺陷并回到来源；通知只对有权用户可见；失败/回滚不产生虚假结果或消息。

### P4：兼容、恢复及系统验证

覆盖旧会话/旧链接、权限撤销、刷新、取消、并发、租约中断、会话丢失、重复请求和项目切换。进行浏览器端到端验收；对依赖真实模型、浏览器或外部服务的部分明确报告验证环境和限制。
