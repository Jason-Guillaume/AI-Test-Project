# 数据库全量清单（P1）

> 下方逐列/依赖快照来自2026-11-13的0081数据库；2026-11-16已复核并将本机库升级至0086。升级后表数为190，DB-only两表保留、ORM-only两表已建；详细前后变化见 [`database_before_after_comparison.md`](database_before_after_comparison.md)。

全量结构审计日期：2026-11-13。范围：当前工作区后端 SQLAlchemy 模型、Alembic历史文件，以及当时本机 `testplatform_dev` PostgreSQL 的只读 catalog。2026-11-16另行采样版本、表数、关键行数与索引并执行迁移；未重生成全量逐列清单。

## 计数与方法

- 2026-11-13采样数据库：**188 张物理表**（`public` 可见，含 `alembic_version`）；应用表 **187 张**。
- 全量 ORM 声明：**187 张表**。按全部模型模块/包初始化文件导入 `Base.metadata` 后实测。
- 初次审计时 Alembic `env.py` 显式装配 `target_metadata` 为 **185 张表**，少注册 `recycle_bin_item`、`data_lifecycle_audit_event`；本轮已修复，当前代码注册 **187 张表**。
- 数据库版本（历史采样）：`0081`；当前代码迁移 head 为 `0086`，共86个 migration revision。
- 0081物理表与 ORM 对照：共有 185 张；ORM 有、物理库缺 2 张（`automation_jenkins_credential`、`test_case_import_batch`）；物理库有、ORM 未声明 2 张（`model_global_migration_audit`、`td_sandbox_task`）。升级至0086后前两张已建成，后两张仍保留；`alembic_version` 另计。
- 全量 ORM JSON 字段 **184 个**，涉及 **103 张表**；有 `deleted_at` 字段的 ORM 表 **62 张**。这些数字不表示 JSON 字段都适合 JSONB 化。
- 列名差异有 4 张表，详见“物理库与 ORM 列差异”。

计数基于 `Base.metadata.tables` 和 `information_schema.tables` 实测，不由文件数推算。数据库只读连接到本机 `testplatform_dev`；未核实其他开发、预发或生产环境。

迁移状态 `0081` 解释了这 4 组差异：API 响应键、Jenkins 扩展字段、Excel 导入批次、组织软删除字段属于之后的代码迁移。字段类型、默认值、约束和索引仍应在迁移链修复后再做逐项对照；不能只以列名相等作为 schema 一致结论。
