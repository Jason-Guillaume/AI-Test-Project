## 存量数据与回滚

从本机开发库 `0097` 通过只读、一致性事务复制所有业务表和序列，在同一 PostgreSQL 实例新建的随机库运行迁移。原 25 张表和 4 张父表按原字段投影，核对行数与行内容摘要。每个阶段检查 29 个对象、59,401 条记录，包含 52,897 条用例明细、181 条接口参数、131 条响应、127 条请求体和 5 条文本模型配置。升级至 `0106`、回滚至 `0099`、再升至 `0106`，三次核对均为零差异。另对 12 个原有模型修订的配置 JSON 原文核对，内容一致。

隔离样本补齐了开发库没有的数据。验证覆盖跨类型公开 ID 重号、独立序列高水位、显式空请求体、摘要过期时间、项目设置版本冲突、同项目集合、步骤级断言、ASR 过期租约和迟到工作器、不同项目连接与参数别名。回滚还原切换后发生的增加、修改和删除。历史建库基线已固定，空库可以从 `0001` 一路升至 `0106`。[跨域回滚测试](../../backend/tests/test_schema_consolidation.py) · [集合与明细](../../backend/tests/test_collection_component_storage.py) · [ASR 队列和审核](../../backend/tests/test_asr_queue_review_migration.py) · [模型中心兼容](../../backend/tests/test_model_storage_migration.py)

统一运行了 230 项相关回归，全部通过。历史单价保存逻辑最后调整后，又单独运行了 5 项模型存储专项测试。检查覆盖旧版读取器的项目隔离、归档恢复、跨版本公开 ID、历史单价和超时。另用两个 PostgreSQL 会话验证，工作器即使在申请行锁时租约有效，拿到锁时若已到期，也无法续租或写入结果。

## 空间与耗时

同一开发库快照在 `0099` 占用 **53.44 MiB**，在 `0106` 首次升级后占用 **52.55 MiB**，其中索引从 **17.83 MiB** 减至 **17.38 MiB**。统计范围是 `public` 下物理表及其索引和 TOAST。两次均取隔离副本，避开开发库既有的空间碎片对比较的影响。

下表为本机 PostgreSQL 16.16 的 P95，单位为毫秒。每项在同一份数据的两个独立库交替取样。接口读写每版取 200 次，队列领取每版取 400 次，测试管理在统一业务回归结束后单独测量，每版取 500 次。测试管理使用 52,897 条合成明细，包含 2,912 条指向步骤的断言。队列样本包含 2,000 个模型运行和 2,000 个处理运行。

| 测量操作 | 合并前 P95 | 合并后 P95 |
|---|---:|---:|
| 接口列表，20 项 | 11.78 | 11.91 |
| 接口详情 | 17.26 | 17.86 |
| 替换两个接口参数 | 12.84 | 13.78 |
| 加锁领取一个模型运行并提交租约 | 7.91 | 6.42 |
| 读取四类用例明细 | 6.35 | 5.93 |
| 用例执行准备 | 4.30 | 4.63 |
| 同事务写入步骤、断言、前置条件和数据 | 10.41 | 11.28 |

接口详情往返从 6 次降到 5 次，列表维持 4 次。四类明细同事务提交的 P95 增加 0.87 ms，约 8.4%。并行运行其他测试时，执行准备的 P95 曾从 83.73 ms 升至 138.45 ms，同一组的 P50 从 6.64 ms 变为 6.49 ms。表中的独立复测用于比较本地结构变化，生产负载的延迟需要在部署环境量测。

## 发布方式

这批迁移在同一事务内锁定涉及的表、转移数据、安装兼容视图和约束。发布时应安排维护窗口，让写请求和 ASR 工作器先结束当前事务，随后使用项目既有的 Alembic 发布入口升级，应用与工作器同时切到配套版本。回滚目标为本次重构前的 `0099`，数据库与应用代码一起回退。开发库当前版本到 `0099` 之间还包含原项目的 `0098`、`0099`，两版均保留在发布链中。[项目启动迁移入口](../../backend/docker-entrypoint.sh) · [项目级设计与各表去向](2026-11-25-project-schema-refactor.md)

本机这 25 张原表均无授予其他数据库角色的对象权限、列权限或行级安全策略。另行设置 PostgreSQL 角色授权的部署，切换及回滚时需按原权限配置恢复对应对象的授权。
