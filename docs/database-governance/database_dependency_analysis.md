## 扫描范围与判读

扫描了后端 5749 个非模型、非测试/迁移 Python 源文件（含脚本/worker入口），使用模型类名与表名进行静态命中；另扫描 244 个测试/验收 Python 源文件、85 个当时的 Alembic 版本脚本和 290 个前端源码文件。命中是静态线索，不等于运行时调用次数；动态 SQL、别名、插件和外部调用需结合人工复核。

前端不直接访问数据库表名，接口服务以 domain API 与 schema 契约耦合。源码目录存在 ASR 评测、测试管理、测试数据、自动化、任务、报告、接口资产、ZAP、模型中心与回收站页面/API；因此表变更仍需沿 Router → Service → schema/序列化器 → `frontend/src/features/**/api` 和页面契约核对。按表名对前端源码精确搜索的命中数列在逐表表格中；零命中只表示没有直接表名耦合，不表示 API 无依赖。

## 运行链路重点

- **ASR**：Worker 与服务对 `asr_job`、`asr_model_run`、各类 work item、内容复核、说话人和分段结果分别使用；队列表有独立租约与唯一键。应以各自 service/worker 的重试、取消、版本快照为迁移边界。
- **测试管理/测试数据**：Router 与 Service 使用用例、步骤、断言、前置条件、Fixture、Provider、执行、池与租约等模型。导入幂等批次目前只存在于 ORM/迁移预期，当前 0081 库尚未创建。
- **业务管理**：Flow/Action 执行、绑定、变量引用、状态和规则经执行服务/变量解析路径使用，外键方向和乐观锁语义应保留。
- **安全测试**：普通安全策略/用例/执行/Finding 与 ZAP 的扫描任务、事件、Finding、目标和认证配置经不同服务及 worker 链路访问；不应按名称/字段相似度并表。
- **Agent/任务**：任务、运行、工作项、尝试、消息、调用事实、事件事实和 trace 投影有不同恢复、幂等、投影/Outbox职责。
- **模型中心**：`ModelConfiguration`、`AsrConnection`、`AsrParameterSet` 仍有旧调用链；`model_center_service.py` 对旧记录执行兼容同步，`model_legacy_binding` 保留映射。迁移 0034 明确回填旧模型、ASR 连接、参数集；不是可以直接删除旧表的证明。

## 无直接生产代码命中的表

当前模型类/表名静态扫描中，测试范围迁移辅助表 `test_scope_api_backfill`、`test_scope_migration_check` 没有非测试业务代码直接命中，但存在数据库外键/迁移代码引用；前者的 0047 downgrade 会用它回滚迁移改写的 `test_case.api_id`。两个物理库有、无 ORM 模型的表为 `model_global_migration_audit` 和 `td_sandbox_task`，其用途与风险见冗余分析。这里的“无直接命中”不能单独作为删除依据。

## 前端/API兼容边界

前端不直接访问数据库表名，接口服务以 domain API 与 schema 契约耦合。源码目录存在 ASR 评测、测试管理、测试数据、自动化、任务、报告、接口资产、ZAP、模型中心与回收站页面/API；因此表变更仍需沿 Router → Service → schema/序列化器 → `frontend/src/features/**/api` 和页面契约核对。按表名对前端源码精确搜索的命中数列在逐表表格中；零命中只表示没有直接表名耦合，不表示 API 无依赖。

没有建议改变 API 请求/响应。若未来替换 ORM 表，需先列出所有相关 Router 响应 schema 和 `frontend/src` 对应 API contract，并保留旧 API 字段与分页/状态语义直到兼容期结束。
