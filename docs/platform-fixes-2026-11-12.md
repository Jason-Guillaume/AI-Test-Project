# 测试开发平台优化方案
2026-11-12 · 开发与测试评审稿 · 代码基线 `develop@9434059`

本次对照反馈截图静态核查了前后端实现。下文的验收项供改动后执行；线上部署版本、失败的原始 OpenAPI 文件和数据库状态尚未核验。第 2 项按平台角色 `admin` 理解，第 4 项按截图解释为搜索框靠左、操作按钮成组右对齐。

## 1. 开发工程师登录后显示为测试工程师

**定位。** 管理端创建账号时以 `body.role` 写入用户，角色标签已有 `dev → 开发工程师` 映射。工作台侧栏单独判断“是 admin 则显示平台管理员，否则显示测试工程师”，因此即使登录用户返回 `dev` 也会显示错误。[建号逻辑](../backend/app/platform/users/services/user_service.py#L169) · [角色映射](../frontend/src/features/identity/components/RoleTag.tsx#L8) · [侧栏硬编码](../frontend/src/app/layouts/ConsoleLayout.tsx#L385)

**改动。** 把平台角色中文名映射导出为共用函数或常量，供侧栏、账号列表和角色选项使用。侧栏从当前登录用户读取角色，加载中显示占位，遇到未知值显示“未知角色”。此问题无需调整账号权限或批量改库。

**验收。** 管理员创建开发账号后，用该账号重新登录并刷新工作台，对照当前用户接口中的 `role=dev`、侧栏和管理端列表。另以 test、admin 各登录一次，三种身份均显示相应中文名。

## 2. 账号与组织独立创建，由平台管理员分配成员

**定位。** 自助注册和管理员建号都会调用 `ensure_personal_organization`。此外，建组织路由只要求登录，服务可直接把调用者设为 owner；成员写入使用组织级授权。仅移除管理员建号时的调用，仍会留下其他建组织或分配人员的入口。[两条建号路径](../backend/app/platform/users/services/user_service.py#L128) · [组织路由](../backend/app/platform/organizations/router.py#L33) · [创建与成员写入](../backend/app/platform/organizations/services/management_service.py#L95)

**改动。**

1. 两条建号路径都只创建账号并保留已有通知行为。首次登录允许零组织，显示“等待平台管理员分配组织”。核查只按 owner 查询的 `_default_org_id` 对通知归属的影响，未分配时允许为空。初始化脚本也调用该帮助函数，应把初始组织作为明确的管理员初始化步骤，与普通建号分开。[初始化脚本](../backend/scripts/seed_admin.py#L155)
2. 在服务端给建组织和分配成员入口统一加平台 admin 校验，覆盖成员新增、改配和移除；负责人转移也需防止绕过集中分配。保留成员查看自己组织的能力。前端按同一权限显示操作。平台角色、组织角色、项目角色分别保存。
3. 既有“Joey 的组织”等先列出负责人、成员、项目及授权引用。管理员确认目标组织后，先核对迁移后的成员访问范围，再转移关联；有业务引用或归属未确认的组织保留。组织名称只用于筛选候选，不能据此自动删除。

**验收。** 分别注册和后台建号，组织数、成员关系数均不增加；未分配账号能登录。普通账号及非平台 admin 的组织负责人直接调用建组织、分配接口均被拒绝。平台 admin 建组织并分配 Joey 后，Joey 可见目标组织；复查其他组织和项目的访问权限。升级前已有组织及其项目仍可读取。

## 3. 新建项目弹窗清空历史输入，仅允许显式取消

**定位。** 页面持续挂载 CreateProjectModal，表单实例创建在弹窗内容外。当前虽有 `destroyOnClose`，Form 仍保留字段，打开时也未重置；遮罩、Esc 和关闭图标未显式禁用。截图中的旧值与这条状态保留路径一致。[弹窗挂载](../frontend/src/pages/admin/Projects.tsx#L238) · [表单实现](../frontend/src/pages/admin/Projects.tsx#L274)

**改动。** 仅在 creating 为真时挂载新建组件，使每次打开取得全新 form；名称、描述、所属组织及校验提示一起复位。设置 `maskClosable={false}`、`keyboard={false}`、`closable={false}`，保留可用键盘聚焦的“取消”按钮。校验或提交失败保留当次输入，成功后关闭。若复测发现仅浏览器候选提示残留，再单独处理自动填充。

**验收。** 填写三项后点击遮罩或按 Esc，弹窗和值保留，无右上角关闭入口。点击取消再打开，三项为空且无旧错误；成功创建 A 后再点新建也为空；模拟服务端拒绝后可在原值上修改并重试。

## 4. 项目列表工具栏右对齐

**定位与改动。** 搜索框、新建、批量删除、回收站是同一 Space 的四个直接子项，整行 `space-between` 将按钮分散。改为搜索区和操作区两个容器，搜索区左对齐，操作组用 `margin-inline-start: auto` 靠右、按固定间距排列三个按钮，末端与表格外沿对齐。窄屏允许操作区整体换行，搜索框最大宽度设为 100%。样式限定在项目页，共用工具栏还有其他调用方。[项目工具栏](../frontend/src/pages/admin/Projects.tsx#L192) · [共用样式](../frontend/src/styles/base.css#L178)

**验收。** 在桌面宽屏与窄屏分别检查空表、有数据、勾选多条三种状态。按钮等高、不遮挡、页面无横向溢出；批量删除计数变化后右边缘仍与表格对齐。

## 5. 添加组织成员时提供可选人员列表

**定位。** 用户名框要求精确搜索。命中后仅写入隐藏 user_id，界面显示编号；改词或查无结果时旧 ID 可能保留，造成输入框所见与实际保存对象不一致。后端候选接口目前只返回单个启用账号。[成员抽屉](../frontend/src/pages/admin/Organizations.tsx#L377) · [候选查询](../backend/app/platform/organizations/services/management_service.py#L200)

**改动。** 用可搜索的单选下拉框绑定 user_id。展开即展示首批启用账号，支持按用户名模糊搜索和分页，选项显示“用户名 · 平台角色”，已在组织内的人员标注“已加入”。新增列表接口并保留现有精确查询契约，权限与第 2 项一致。清除或改搜时撤销旧选中值，只有明确选择才能保存；请求以组织和关键字区分，忽略过期响应。后端保存时复查用户启用状态和权限。编辑已有成员时固定原用户，回显实际组织角色。组织列表默认选中第一项时，成员和模型查询也应使用同一个有效组织 ID，当前查询依赖初始为空的 activeId。[查询与默认选中](../frontend/src/pages/admin/Organizations.tsx#L63)

**验收。** 首次打开有候选；有搜索结果、无匹配、加载失败三种状态可区分。选 A 再改搜 B，未选 B 时无法提交；选中 B 后仅 B 成为成员。停用账号不能分配；切换组织时不带入旧选择。

## 6. OpenAPI 导入预览成功，确认阶段返回 500

**定位。** 截图显示预览识别 23 个接口，确认请求返回 500。解析器把 default、2XX 及其他非数字键统一映射为 0；预览使用的 InternalResponse 只要求整数。确认阶段重新解析，在写子记录时构造要求 100–599 的 ApiResponseIn，触发反馈中的 ValidationError。服务在整批末尾才 commit，之前的 flush 并非已提交。[解析器](../backend/app/features/api_catalog/parsers/openapi_parser.py#L464) · [内部模型](../backend/app/features/api_catalog/schemas/internal.py#L38) · [写入校验](../backend/app/features/api_catalog/schemas/requests.py#L34) · [确认事务](../backend/app/features/api_catalog/services/import_service.py#L116)

**修复分两步。**

1. 先统一预览与确认的可写性检查。在整数模型过渡期，遇到暂不能保存的键，在预览标出方法、路径、原始响应键及原因，允许取消勾选受影响接口并导入其余项。直接确认含问题项时，在写库前返回带定位的 422。捕获范围限定为输入解析和契约校验；数据库异常按既有事务机制回滚。避免丢弃响应定义、放宽到 0 或伪造 200。
2. 完整支持原始响应键。为响应定义增加字符串 response_key，覆盖具体码、范围及 default；保留可空的数值 status_code 供旧数值逻辑使用。先扩表并回填历史具体码，再部署兼容读写，最后开启范围键写入。同步改内部模型、请求与详情契约、替换写入、结构哈希、差异比较和前端显示，调试实测状态码仍为整数。对未知键给出明确错误，按文档版本处理允许的键；匹配顺序为具体码、对应范围、default。[现有非空整数列](../backend/app/features/api_catalog/models/api_response.py#L31) · [按整数比较差异](../backend/app/features/api_catalog/services/change_diff.py#L35)

**验收。** 最小样本在同一接口声明 200、2XX、default，分别附不同描述。完整修复后预览、确认、详情均保留三条及描述，再导入无变化。分别用 0、600 和非法键验证错误定位；混合文件选中非法项时接口主表、响应表与导入记录均无部分提交。用原始 23 接口文件复验所选数、创建/更新/跳过数和响应详情。

## 7. 测试用例支持 Excel 批量导入

**现状。** 截图中的用例页已有“手工用例”和“生成草稿”。单条创建会检查项目写权限、名称和枚举，挂接范围并提交；前端随后可移动到当前目录。仓库还有按特定文件名处理资产的离线脚本，可参考其读取工作簿的方式。直接循环调用单条创建会在中途失败时留下部分数据。[页面入口](../frontend/src/pages/console/TestManagement/TestCases.tsx#L378) · [单条创建](../backend/app/features/test_management/services/case_service.py#L156) · [离线脚本](../backend/scripts/import_spreadsheet_assets.py#L68)

**首版建议。** 在“手工用例”旁增加“导入 Excel”，提供模板下载、上传 .xlsx、预览、确认四步。当前项目、API/UI/AI 页签、选中目录显示在预览顶部并锁定为本次目标。首版一行代表一条用例，覆盖基本信息；步骤和断言如需结构化执行，可后续扩展关联工作表。

| 模板列 | 写入与校验 |
| --- | --- |
| 用例名称（必填） | 去首尾空白，1–200 字；文件内重名及项目已有同名均提示对应行 |
| 优先级 | P0–P3，空值按手工创建默认 P1 |
| 测试维度 | 提供页面已有选项，转换为后端枚举；空值为 FUNCTIONAL |
| 用例描述 | 可空，最多 1000 字；保留换行 |

例如，模板第 2 行可填“有效账号登录成功 / P1 / FUNCTIONAL / 校验登录后显示的用户名”。导入后归属当前项目、方向及选定目录；在“待整理”中发起则落入对应方向的待整理范围。[字段与默认值](../backend/app/features/test_management/schemas/cases.py#L25)

**接口与提交。** 建议增加项目级模板下载、预览、确认接口。预览只读，返回有效数和“工作表、行、列、原因”；校验表头、损坏文件、文件大小及展开后的行数。确认复核权限、目标目录所属项目和方向、文件摘要及重名情况。抽取单条创建与目录挂接的无提交逻辑，让批量服务在一个事务内创建、归档到目标目录并记录来源；沿用 MANUAL，批次记录保存导入人及文件摘要。为一次确认生成幂等键并加数据库唯一约束，双击和网络重试返回同一批次结果。将 Excel 解析依赖纳入后端运行环境。

**验收。** 在 API、UI、AI 页签分别导入两条有效记录，核对目录、数量、优先级和详情。另测空文件、错表头、非法枚举、同文件重名、项目内重名、跨项目目录、只读账号、重复确认及中途写入失败。错误可定位到具体行列，失败批次写入数为零；成功后刷新目录计数和用例列表。

## 建议实施顺序

先交付第 6 项的导入错误定位与事务回归，同时修复第 1、3、4 项。第 2、5 项一起发布，确保管理员能够从可见候选中完成分配，再收紧旧入口。带数据库迁移的响应键支持和 Excel 批量导入分别验收，前者以原文档无损导入为准，后者以重复提交、整批回滚和目录归属为准。
