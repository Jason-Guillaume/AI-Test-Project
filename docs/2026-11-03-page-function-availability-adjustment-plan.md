# 页面与功能可用性扫描及调整方案

审查日期：2026-11-03（Asia/Shanghai）。对象：当前工作区代码、正在运行的本机前端 5173、后端 8001 和本机开发库。本文是调整方案，本轮未修改业务实现、迁移数据库、重启服务或提交真实业务任务。

## 1. 结论

当前问题集中在 **执行依赖缺失、部分功能入口断开、模型中心迁移后的业务断链，以及错误恢复和分页不完整**。不能把“页面能打开”当成功能可用，也不能把没有业务数据的空表认定为故障。

- 已在登录态浏览器访问 **38 个固定入口地址（含旧入口重定向）和 2 个已有 ASR 详情页**，另切换了安全测试、Web UI、数据中心的 **9 个内部标签页**。本次未复现整页“页面暂时无法显示”。
- 截图确实对应 `AppErrorBoundary` 的全局错误兜底。当前 ASR 任务列表、新建表单及“每日夜间”表单可打开；原始异常堆栈尚未取得，**不能宣称截图故障已修复或归因完成**。
- 实际阻断已经确认：**ASR Worker 离线；ASR 项目只有 2 个可用转写模型，而三方评测要求 3 个不同资源；说话人模型为 0；ZAP 未启用且扫描页面未接入入口；统一模型中心来源的候选参数复跑返回 400；37 条 ASR 任务的列表最多只能浏览到前 20 条。**
- 类型检查、Lint、14 项前端测试、生产构建，以及 ASR/模型中心 41 项隔离测试均通过，仍未覆盖上述业务断链。

建议按“恢复依赖与可诊断性 → 修复业务闭环 → 补齐入口与降级 → 完整验收”的顺序处理，暂不扩大功能范围。

## 3. 已确认的问题与调整要求

优先级定义：P1 为核心流程阻断或关键功能入口缺失；P2 为局部功能、恢复能力、规模化数据或体验问题。截图异常单独保留为高优先级排查项，不用未经证实的原因替代诊断。

### A01 / P1：截图中的全局错误尚未归因，故障恢复范围过大

**证据：** 截图文案与 `frontend/src/app/router/AppErrorBoundary.tsx:30` 一致。边界挂在认证和全部路由外层，任一路由模块加载或渲染异常都可能移除导航外壳；错误状态没有随路由变化复位，只提供刷新。当前浏览器复查未复现原异常。

**调整：** 保留根级最后兜底，同时在控制台/管理端布局的内容出口设置路由级边界，异常时保留项目选择和导航；提供局部重试、返回工作台。记录错误编号、路由、前端构建版本、错误堆栈及相关请求 ID；区分模块下载失败和业务渲染异常。遇到过期构建资源时最多自动恢复一次，防止刷新循环。

**验收：** 模拟页面组件抛错及 chunk 加载失败，其他页面仍可进入，故障页可恢复；再次复现截图时能够凭错误编号定位到具体异常。没有原始堆栈前，此项不关闭。

### A02 / P1：ASR 后台执行器离线，常规启动流程缺少独立 Worker

**证据：** 浏览器与 `/asr/runtime-status` 均显示离线，页面最近心跳为当日 12:01:16。`backend/app/main.py` 启动 TaskWorker 和可选 ZAP Worker，没有启动 ASR Worker；ASR 有独立脚本 `backend/scripts/run_asr_worker.py`，但 `compose.yaml` 和根启动指南没有对应启动项。本次检查时 ASR 待执行 work item 数为 0，未发现当前积压，不能表述为已有任务正在大面积卡队列。

**影响：** 新建 ASR 评测、夜间计划、媒体分析和独立说话人处理不能依靠仅启动 Web 后端完成。

**调整：** 将独立 ASR Worker 纳入正式启动和部署，配置自动重启、心跳检查、日志、优雅退出与并发限制；在项目就绪检查中显示执行器状态。离线时表单明确说明“可排队、待执行器恢复”，显示排队时间和恢复指引。

**验收：** 按启动指南可得到在线心跳；使用合成 Provider 完成排队、领取、执行、持久化；停止 Worker 后界面准确降级，重启后恢复未完成任务，且不重复提交。

### A03 / P1：当前三方评测所需模型数量不足，表单没有提前拦截

**证据：** 只读检查显示项目 #2 可用 ASR 模型为 2 个，项目 #1 为 0 个；`job_service.py:84` 和 `assets_service.py:443` 要求三个槽位对应不同模型资源。前端三个下拉复用相同选项，没有槽位去重校验。

**影响：** 当前项目 #2 即使每个槽位都选了值，也无法满足三方任务/计划的服务端条件；模型单独诊断成功并不能证明三方评测可创建。

**调整：** 按现有三方产品规则，先补齐并授权第三个真实参考模型；前端显示“2/3 个资源就绪”，禁用重复选项，提交前校验唯一性。若业务只需要一个或两个模型，应单独提供对应运行模式，明确输出范围，不自动伪造第三方结果。

**验收：** 模型不足或重复选择时在表单内说明原因；三个合格资源齐备后即时任务和夜间计划均能创建并执行。模型配置与授权由管理员完成。

### A04 / P1：统一模型中心来源的候选参数复跑失败

**复现：** 在独立内存 SQLite 中创建三个模型资源、参数方案和合成音频，使用 `model_slots` 创建三方批次，写入合成识别结果并建立对比，创建候选参数实验。调用 `run_experiment` 返回 **400：计划必须包含一个待测连接和两个参考连接**，实验被保存为 `FAILED`，没有候选任务。

**原因：** `comparison_service.py:752` 仍构造旧 `connection_ids + parameter_set_id` 请求；新模型资源的兼容连接不携带旧 TEST/REFERENCE 角色。旧校验拒绝这些连接。失败后前端又只允许 DRAFT 启动，使该实验无法直接重试。

**调整：** 从原批次 `ModelTaskSlot`/运行快照继承资源、修订、角色和参考参数版本，仅为 TEST 创建候选参数版本；使用新槽位入口创建候选任务。候选参数、任务和实验关联应有一致的事务边界。对启动失败提供明确的可重试状态或复制草稿动作，并显示后端原因。

**验收：** 模型中心来源和遗留来源分别覆盖“重新请求参考/复用参考”两条路径；候选只改变 TEST 参数，参考版本保持一致；创建失败不会留下误导性的 RUNNING 或永久不可恢复状态。复现脚本见附件。

### A05 / P1：ZAP 扫描界面存在源码，但没有可访问入口

**证据：** 安全工作区只注册概览、策略与规则、安全用例、疑似问题四个标签。`ZapScanTab.tsx` 没有被入口引用；从 `src/main.tsx` 的构建依赖图检查，**15 个 ZAP 页面/面板文件不可达**，包括目标、认证配置、扫描配置、任务、结果、向导与详情面板。

**影响：** ZAP 目标配置、启动向导、扫描任务与报告无法从现有界面访问。后端 API 存在不能补偿前端入口缺失。

**调整：** 在安全工作区恢复明确的“安全扫描”入口及对应深链接，接回现有 ZAP 组件，恢复任务和结果回链；将常规安全用例与扫描能力的状态分别展示。

**验收：** 从导航可进入目标、认证、扫描配置、任务和结果；刷新深链接仍进入同一资源；项目切换后范围一致；既有任务链接可回到正确详情。

### A06 / P1：本机 ZAP 服务开关关闭

**证据：** 当前加载的 `settings.ZAP_ENABLED` 为 false。这是与 A05 独立的配置阻断。

**调整：** 对需要扫描的环境配置 ZAP 服务和 Worker、访问凭据及健康检查；未启用时界面说明依赖缺失并提供配置入口，避免点到执行时才失败。恢复入口不应自动触发扫描。

**验收：** 关闭时准确标为未启用；启用且服务可达后可完成获授权测试目标的预览、确认、执行、结果读取和报告回链。真实扫描需在专门验收环境进行。

### A07 / P2：ASR 列表分页只处理已下载第一页，历史记录不可达

**证据：** `JobsPage.tsx:95` 固定请求后端第 1 页、每页 20 条，再用本地表格每页 10 条分页。当前项目实际有 37 条任务，浏览器只显示两个分页，**后 17 条不能通过列表访问**。音频页同样只读取前 100 条；识别对比页只读取后端前 20 条且没有下一页入口。新建任务的音频选择器也限制在前 100 条。

**调整：** 列表统一使用服务端分页，将 page/pageSize 纳入查询 key，并接回 total/onChange；选择器改成搜索加分页或明确的增量加载。切换项目和筛选后复位页码。

**验收：** 用 37 条任务、101 条音频、21 条对比验证末页均可访问；可选择第 101 条音频；翻页、刷新和项目切换不混用数据。

### A08 / P2：独立说话人功能没有可用模型

**证据：** 两个项目的可用 DIARIZATION 资源均为 0。单模型工作台显示“没有可用的说话人模型，请联系平台管理员配置或授权”，启动按钮禁用。

**调整：** 配置并授权 DIARIZATION 类别资源和参数方案；在工作台提供就绪检查和管理员配置指引。原生 ASR 说话人标签与独立分段模型分别展示能力来源。

**验收：** 有授权模型后可以启动独立处理并查看结果；没有模型时仍可查看原转写和已有原生标签，说明准确且不影响其他操作。

### A09 / P2：可选依赖失败会封锁整个任务列表，部分错误被当作无选项

**证据：** `JobsPage.tsx:235` 等待任务、模型、可选说话人模型、音频和计划全部返回；238–240 行任一模型/计划读取错误都会替换任务页。音频读取错误没有单独错误分支，最终可能被折成空选项。运行状态查询失败也可能长期保留“正在检查 Worker”文案。

**调整：** 将“历史任务列表”“创建表单依赖”“夜间计划”“执行器状态”分别加载和报错；可选说话人模型失败不阻断历史任务。为音频选择与运行状态提供明确失败和重试入口。

**验收：** 分别模拟音频、模型、说话人模型、计划和心跳接口失败；仍能查看已有任务；只影响对应操作，界面不误报“没有数据”或无限检查。

### A10 / P2：旧模型入口将普通成员直接送往无权限的管理端

**证据：** `/console/asr/connections` 无条件重定向到 `/admin/model-configs?category=ASR`，`/console/model-center` 同样重定向管理端，后者有 RequireAdmin 保护。本次以管理员确认了旧 ASR 入口重定向；普通成员的 403 路径为代码核对，尚未使用普通账号浏览器复验。

**调整：** 旧入口按身份展示：管理员进入配置；普通成员进入可用模型只读说明页或明确的管理员协助提示。维持现有后端权限，不为兼容书签扩大权限。

**验收：** 普通成员使用旧书签可得到可理解的状态和返回入口；管理员仍可进入模型配置；接口权限不放宽。

### A11 / P2：Agent 治理中的部分工具只有目录登记，没有任务执行实现

**证据：** 工具页和 `backend/app/tools/catalog.py` 明确将 `business.list_flows`、`test_asset.save_cases`、`web_ui.generate_draft` 标为 catalog_only；最后一项的独立 Web 编写流程存在，不等于该工具键已接入统一任务执行器。网络搜索、交互式 Shell 及任意 Shell/Python/HTTP 自定义工具也未开放对应执行能力。

**调整：** 治理目录与实际可运行能力采用同一份能力声明；目录项可查看说明，但任务执行选择器不应把它们展示成已可运行。按真实业务优先级接入流程查询、保存用例和 Web 草稿工具，并补权限、人工确认和调用记录。

**验收：** 每个标为可运行的工具都有实际执行路径和可核对的调用记录；目录登记、Agent 绑定、独立工作区能力不再混淆。

### A12 / P2：调参建议以同步请求执行，长耗时场景存在超时风险

**证据：** `/asr/comparisons/{id}/suggestion-jobs` 的实现和注释均为同步调用，直接执行文本模型；共享前端请求超时为 30 秒。本轮没有执行真实文本模型，**尚未复现实际超时**。

**调整：** 改成持久后台建议任务，202 返回 job_id，可查询状态和结果；按对比版本、已确认片段版本、模型/参数修订建立幂等边界，显示规则降级来源。不能靠无限延长前端超时解决恢复问题。

**验收：** 合成 Provider 延迟超过 30 秒，前端仍能跟踪任务；刷新或重复点击不重复计费；失败、规则降级和正常模型输出明确区分。

## 4. 当前明确未实现的功能，单列为范围缺口

这些内容不应作为“修一个页面错误就会恢复”的承诺；需要进入独立需求清单。

| 模块 | 当前能力边界 | 建议 |
|---|---|---|
| 业务管理 | 规则表达式仅人工维护，不自动执行；移动端绑定不能用于执行 | 展示能力标签；优先完成现有 API/Web 闭环，再决定表达式执行和移动端排期 |
| 报告 | PDF/Word/Excel 导出、匿名公网分享、跨项目聚合未接入 | 明确可用导出范围；需要时另立导出与分享需求 |
| 缺陷 | 回归关联、趋势看板、修复时长统计尚未接入 | 先验收现有来源关联与状态维护，再补回归和趋势 |
| Agent | catalog_only 工具、网络搜索和交互式 Shell 不具备当前任务执行能力 | 以实际运行能力控制选择器与说明，不将治理配置保存成功视为执行成功 |

上述边界依据当前代码实现、显式 UI 提示及模块说明交叉检查；注释中的历史 Phase-1 描述不单独作为功能缺失证据。
