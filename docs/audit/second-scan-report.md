## 1. 结论摘要

本轮确认 **2 项新增/重新确认的问题**，均为 P2：

1. 多个批量选择器和接口树仍直接读取所有分页，绕过 `pagination.ts` 的 50 页 / 5000 条保护，数据增长时可造成大量请求及前端内存占用。

首轮的依赖风险 `DEP-001` 仍开放：本轮 `npm audit` 复测列出 4 个受影响依赖项（3 中危、1 高危）。后端 pytest 因缺少 `psycopg` 未能进入测试体；当前 CUA 没有可用浏览器，无法进行逐页 UI 验收或截图。没有确认新的 P0/P1 业务缺陷；这不代表运行时权限、数据库事务或所有页面交互均通过验收。

## 4. 问题清单

### RESCAN-001 — 批量分页请求绕过安全上限

- **分类 / 严重度 / 优先级**：性能与功能完整性 / 中 / P2
- **模块**：接口目录、统一任务、控制台项目选择器
- **状态**：静态分析确认；大数据量影响未动态复现
- **证据位置**：
  - `frontend/src/pages/console/ApiCatalog/ModuleTree.tsx:63-70`：按 `first.total` 计算页数，并对剩余页执行无上限 `Promise.all`。
  - `frontend/src/components/tasks/TaskCreateModal.tsx:54-64`：`loadAllPages` 根据返回总数并发读取所有页面；该函数用于项目、Web 登录态、安全 API 与策略候选项。
  - 同文件 `:91-107`：API 用例采用无最大页数的循环；Web 用例按返回总数一次并发读取所有页。
  - `frontend/src/layouts/ConsoleLayout.tsx:198-210`：控制台项目选择器同样根据 `total` 并发加载所有页。
  - `frontend/src/api/pagination.ts:1-51` 已提供 50 页 / 5000 条上限及超限报错，但以上路径未统一使用该工具。
- **影响与复现**：创建包含大量接口、项目、用例或登录态的隔离测试数据，再打开接口树、任务创建弹窗或控制台项目选择器，即会触发随 `total` 增长的额外请求。若数据量足够大，页面会同时保留全量数据并产生大量并发请求；API 用例分支则会持续逐页请求。普通规模下不一定可见，尚未量测实际延迟或内存。
- **建议修复**：优先为树和候选列表增加服务端搜索 / 按需分页；必须全量读取的路径统一调用 `collectPages` / `collectArrayPages` 并展示超限错误态。给 API 用例循环增加页数上限、取消信号和稳定的分页终止校验。补充边界测试覆盖总量大于 5000、空中间页及请求失败。

### RESCAN-002 — 跟踪文档残留数据库样例凭据

- **分类 / 严重度 / 优先级**：敏感信息与文档配置 / 中（值是否有效未知）/ P2
- **模块**：本地启动文档、开发规范、测试数据
- **状态**：文件内容静态确认；凭据可用性与是否曾用于真实环境待验证
- **证据位置**：
  - `local-startup-guide.md:150` 仍要求核对 Compose 的 `root/[已脱敏]` 凭据。
  - `.claude/skills/develop-this-project/SKILL.md:475` 仍记录同一数据库用户名与已脱敏密码。
  - `backend/tests/test_18_test_data_crud.py:570-577` 使用相同字面量作为目标数据库配置 CRUD 测试数据；这只是测试输入，不能据此认定平台数据库正在使用该凭据。
  - `compose.yaml:7-12` 当前要求显式提供 `POSTGRES_USER`、`POSTGRES_PASSWORD`、`POSTGRES_DB`，并将宿主机端口绑定到 `127.0.0.1`；与启动指南的固定凭据说明不一致。
- **影响与复现**：仓库检索可在跟踪文件中找到被脱敏的数据库样例凭据；启动文档可能诱导开发者复用旧口令，或导致依照文档启动失败。当前 Compose 不再接受文档所述默认值，因此没有证据表明其能认证当前数据库。未检查其他历史版本、部署环境或真实凭据库。
- **建议修复**：将文档示例替换成明确不可用的占位符，并描述通过本地环境变量配置；确认该值是否曾用于共享数据库，若是则轮换。测试夹具改用明显虚构的测试常量，并加仓库密钥扫描，避免文档与测试再使用同一个看似真实的口令。
