## 结论与验证边界

项目可以继续优化，优先级应是交互正确性、入口与信息层级、再扩展业务闭环。现有目录拆分已经改善代码组织，但没有消除用户需要理解多个业务模块、Agent 角色及运行状态的负担。

本次检查了控制台导航、Agent 会话、统一任务创建与详情、响应式样式以及相关后端契约。5173/8001 未发现监听服务，未进行登录后的浏览器视觉验收；下述代码行为与布局规则来自静态检查，不能据此声称实际像素布局已验收。工作区已有大量未提交变更；本次仅新增此审查文件，没有修改应用代码或运行数据库测试。

## 前端简化方案

1. **把入口收敛到六组**：工作台、任务、资产、结果、项目设置、管理。当前控制台有 19 个菜单叶子且各组不折叠。接口、业务、用例、套件、数据、Mock 进入资产下的二级入口；执行历史、报告、缺陷进入结果。保留原地址与深链接，先调整导航再考虑路由迁移。
2. **任务作为统一主线**：用户围绕“目标→方案→确认→执行→结果”操作。AI 助手作为任务创建与持续沟通入口；API、Web、安全页面保留专业编辑能力。从业务页发起任务时自动带入项目和已选资产。
3. **任务页默认展示摘要**：顶部固定目标、状态、阻塞原因与下一步；中间显示对话和阶段进度；侧栏显示结果。参与者、工具审计、调度工作项与完整事件放到高级详情。不要要求普通用户先理解 MAIN、Planner、Worker 才能操作。
4. **结构化结果替代 JSON**：当前 Agent 计划、执行结果、分析和任务事件直接输出 JSON。默认显示范围、数量、失败原因、证据及下一步；原始数据放到折叠详情。审核复选框与卡片合并为同一条记录，避免同一个用例出现两遍。
5. **渐进式创建表单**：先选目标、环境与范围，Agent 配置、步数预算等移入高级设置。`TaskCreateModal.tsx:102–120` 在 API 模式也读取 Web 登录态、安全 API、策略和会话，应按类型启用；大量选项改为服务端搜索分页。
6. **重新安排窄屏审核动作**：`workspace.css` 在容器宽度 ≤1100px 时把三栏改为互斥面板；当前勾选发生在工作区，确认按钮却在对话，导致来回切换。将选择计数、确认与执行放在工作区固定操作栏；中等宽度采用对话加可收起结果栏，小屏用单栏与底部操作区。
7. **统一展示规范**：任务抽屉复用统一状态中文映射；阶段、错误、时间格式一致；图标按钮补充可访问名称。收敛散落的 11/12px 字号与硬编码颜色，主内容采用统一字号与主题 token。

建议的首轮验收：1440/1024/768/390px 检查主要工作流；特别覆盖长标题、长 JSON/错误、100 条以上资产、请求失败、零选择、跨项目切换、刷新恢复以及键盘操作。表格可以局部横向滚动，页面主体不应被撑宽。

## 已具备的基础与适合扩展的功能

当前统一任务已具备计划审批、暂停/恢复/取消、可重试工作项、运行历史链接、消息/事件和业务产物引用；报告已有失败聚类。不要把这些整体重新包装成“尚未实现的新功能”。下列是基于已检查接口的扩展建议，并非全仓库能力缺失证明。

| 建议 | 对用户的价值 | 可复用基础与新增工作 | 顺序 |
| --- | --- | --- | --- |
| 待我处理中心 | 集中展示方案待确认、模型配置阻塞、失败待处理，直接跳到对应动作 | 复用任务状态和命令；增加聚合查询、权限过滤与针对性跳转 | 第一批 |
| 任务模板与“再跑一次” | 常用回归不再重复选环境、范围和参数 | 复用创建接口与 input_snapshot；增加模板持久化、版本和失效资产提示。执行前重新校验权限、环境与可执行范围 | 第一批 |
| 运行对比 | 一眼看到新增失败、已修复、耗时变化 | 复用 TestRun、报告和失败聚类；新增按稳定用例身份对齐的比较接口及页面，标记环境/版本差异 | 第二批 |
| 失败处理闭环 | 从失败证据直接进入重试、缺陷或修复后的验证 | 复用已有工作项重试、缺陷、产物引用；增加入口串联及去重。工作项重试与仅重跑失败用例需区分，后者要处理依赖和前置数据 | 第二批 |
| API 变更影响分析 | 接口字段变化后提示受影响用例并生成定向回归草案 | 结合接口变更记录和资产关联，补影响计算与确认界面；先规则匹配，再用 Agent 解释建议 | 后续 |
| 定时/CI 触发回归 | 每日或发布时自动生成任务并通知结果 | 在现有任务队列上增加触发器、幂等和并发策略；不要另建执行引擎 | 后续 |

## 建议实施顺序

- 第一步：修正零选误确认、跨项目残留、失败输入丢失和异常态；补对应行为验证。
- 第二步：精简导航、任务默认摘要、结构化结果、合并审核操作及分级布局；做浏览器验收。
- 第三步：先增加待我处理中心和任务模板，再增加运行对比与失败闭环。
- 较大架构演进：当前 AI 助手仍经 `agents/router.py` 调用 legacy graph，统一任务则使用另一套运行接口。统一前端入口时先明确“会话生成资产”和“持久化执行任务”的边界，通过任务/产物链接串联；完整合并需补会话与 task/run 映射、历史兼容及长任务状态协议，不宜只改页面名称。
