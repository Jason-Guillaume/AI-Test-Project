# 前端工作区宽屏布局优化方案

目标是让侧栏之外的空间优先用于展示业务数据。打开接口管理页时，用户应能看到更完整的接口名称和路径。控制台和管理后台的同类页面应使用相同的左右边距，手机上仍能访问目录、筛选和详情。

## 现状与组件选择

| 位置 | 当前行为 | 实施决策 |
| --- | --- | --- |
| 公共页面容器 | `.page-container` 宽度为 100%，最大宽度为 1680px，水平居中。面包屑位于容器外，宽屏下两者左缘错开。 | 列表和工作区填满父容器，沿用现有断点与边距。 |
| 接口管理页 | 桌面使用 Ant Design 的 Row 和 Col，模块目录占 320px。窄屏已有「切换目录」抽屉。 | 复用两种布局，把宽屏新增空间分给右侧表格。 |
| 模块接口表 | 名称列宽 220px，路径列宽 320px，路径文本本身还限宽 290px。 | 让长文本列吸收剩余空间，同时保留完整路径提示和复制能力。 |

项目已经使用 React 18 和 Ant Design 5，仓库也约定复用共享 UI。此次采用现有布局、表格、树和抽屉组件，仅调整布局配置和必要样式。图二中 shadcn/ui 的 Dashboard 可供对照侧栏、页头和数据表的排列。引入第二套组件库会增加主题和交互适配工作，而且外层的 1680px 限制仍需单独处理。[Ant Design 5 布局示例](https://5x.ant.design/components/layout/) · [shadcn/ui 页面示例](https://ui.shadcn.com/blocks)

## 实施顺序

1. **记录基线。** 使用同一项目、模块和一组长名称、长路径数据，在 1440px 和 2560px 的浏览器视口截图。记录主内容区宽度、面包屑和筛选栏左缘、路径文本可用宽度。尺寸以 CSS 像素为准。先保存当前工作区状态清单，保护已有业务改动。
2. **调整共享容器。** 从 `frontend/src/shared/ui/PageState.tsx`、`frontend/src/styles/base.css` 和 `frontend/src/styles/responsive.css` 入手。解除业务页面容器的最大宽度，保留容器查询；正文和面包屑共享同一水平边距，沿用现有桌面 32px、中间断点 24px、手机 16px 的正文设置。检查控制台与后台中使用其他容器的页面，仅处理会造成同类留白的规则。表单输入区、登录卡片和阅读正文按内容保留局部限宽。
3. **打通接口管理页。** 在 `frontend/src/pages/console/ApiCatalog/index.tsx` 核对桌面双栏和窄屏目录入口，在同目录的 `ModuleApiList.tsx` 调整名称列、路径列及其文本宽度。方法、状态、版本、时间、操作列只占所需空间；当列宽总和超过可用空间时，在表格内部横向滚动。使用现有表格、提示和复制组件。
4. **推广与收尾。** 抽查任务列表、工作台、后台用户管理和一个单列表单。优先复用共享修正，仅为可复现的局部问题调整页面。公共布局和接口表格的差异分开核对，以便独立回退。

## 验收与交付

| 场景 | 合格条件 |
| --- | --- |
| 1920px、2560px 桌面 | 展开和收起主侧栏后，工作区均填满剩余宽度；面包屑和筛选栏左缘对齐，误差不超过 2 CSS 像素。 |
| 同一接口在 1440px、2560px 下对比 | 宽屏能显示更多路径字符，或已显示完整路径；复制所得字符串始终完整。选择模块、筛选、翻页、进入详情均可用。 |
| 390px 手机 | 导航可收放，目录抽屉可打开和关闭，筛选按钮可达。表格可横向滚动，整页无横向溢出。 |
| 管理后台、表单和工作台 | 数据列能利用新增宽度，单列表单仍易读；切换侧栏后卡片和字段均可见，键盘能到达主要操作。 |

在 `frontend` 目录运行 `npm run typecheck`、`npm run lint`、`npm test` 和 `npm run build`，并从现有 Playwright 场景中选择覆盖实际改动入口的用例。在交付说明中列出改动文件、前后截图或尺寸实测、检查结果及未验证项。上述数值为验收目标，基线和改后实测在实施阶段填写。
