# 前后端项目审查报告

审查日期：2026-10-28。范围：项目路由及前后端主要功能域，重点追踪接口管理、测试执行、业务管理、数据中心、Mock、安全、报告、任务、通知及后台配置；结合用户提供的接口管理截图。审查基于当前工作区，接口管理的两个文件已有未提交修改，结论包含这些修改。本次为静态扫描及有限验证，并非所有业务代码的逐行审计或完整端到端验收。

## 总体结论

发现跨模块的高优先级问题：测试资产及执行中心列表截断、安全概览数据可能失真、接口结构指纹可能过期、业务流程 API 动作缺失 Mock 上下文，以及多个模块列表和选择器无法访问后续页。另有读取失败伪装为空、搜索输入受控状态异常、切换项目后保留旧接口等问题。构建通过不代表业务均可用；由于数据库和服务未运行，本次无法确认所有功能或页面正常。

## 截图中的「结构指纹」

不建议在普通用户的「基本」信息中常驻展示。它是根据接口结构计算的 SHA-256，用于导入去重、判断结构是否变更，而不是接口的业务属性；其本身也不足以告诉用户变更了什么。建议后端继续保留，在「历史 / 高级诊断」按需展示，并用说明解释用途。若保留复制功能，显示可缩写，但应明确复制完整值；目前基本页复制的是前 16 位，历史页复制前 12 位，不是完整指纹。参见 `frontend/src/pages/console/ApiCatalog/tabs/OverviewTab.tsx:98`、`tabs/HistoryTab.tsx:62` 和 `backend/app/features/api_catalog/services/hash.py:1`。

指纹不是密码；不能仅凭截图认定其泄露敏感信息。它所依据的结构可能包含示例等数据，仍应避免将其当成安全凭据或完整变更说明。

## 发现的问题

### P1-1 接口编辑后指纹与真实结构可能不一致

**证据**：`backend/app/features/api_catalog/services/api_service.py:599` 保存请求后，只有 `_diff_params` 或 `_diff_body` 返回变化才重算指纹；`:840` 的参数差异只比较参数名、类型、必填，请求体只比较类型和 Content-Type。参数位置、schema、示例、默认值及请求体 schema/raw 内容等改变可能不触发。`:632` 的响应保存仅比较状态码集合（`:864`），同状态码下的响应 schema 修改不会触发。指纹计算却包含这些字段（`services/hash.py:22`、`schemas.py:47`）。

**影响与复现**：导入接口后，仅修改已有响应的 schema 并保存，再预览原始导入文件；原始指纹仍等于数据库旧指纹，导入被判为 UNCHANGED，即使数据库中的实际响应已不同，跳过应有的更新或差异提示。请求字段也有类似风险。此结论来自代码路径，尚未在数据库中端到端重现。

**建议**：保存后从实际持久化结构统一重算完整指纹，差异记录与指纹判断采用一致的字段语义；补充仅改 schema、参数位置、示例及响应体的回归测试。

### P1-2 Mock 管理列表超出首屏上限后无法访问后续数据

**证据**：服务列表固定取第 1 页 100 条（`frontend/src/pages/console/MockManagement/ServiceList.tsx:319`），接口列表固定取第 1 页 100 条（`ServiceDetail.tsx:164`），场景固定取第 1 页 200 条（`EndpointView.tsx:68`）；三处表格均关闭分页，忽略总数。

**影响与复现**：分别创建超过上限的服务、接口或场景，后续数据不会出现在对应列表，无法通过该列表查看、编辑或删除。建议采用服务端分页并展示总数，覆盖边界值及末页。

### P1-3 接口关联、Mock 选择器和 Web 流程选择器仅有前 200 条

**证据**：`frontend/src/pages/console/ApiCatalog/tabs/RelationTab.tsx:69`、`MockManagement/ServiceList.tsx:228`、`MockManagement/ServiceDetail.tsx:74` 固定请求接口首页 200 条；`WebUI/index.tsx:51` 固定请求业务流程首页 200 条。下拉选项使用这一页，未加载后续页。

**影响**：数据超过 200 条后，用户无法选择后续接口创建关联或 Mock，也无法选择后续业务流程绑定或作为生成上下文。下拉本地搜索无法找回未请求的数据。建议提供服务端搜索和分页 / 按需加载，并显示加载失败状态。

### P2-1 Mock 读取失败显示成「没有数据」

**证据**：上述三个 Mock 列表使用 `data?.items ?? []`，渲染只区分 loading 和空数组，未检查列表查询的 `isError`（`ServiceList.tsx:324,563`、`ServiceDetail.tsx:169,424`、`EndpointView.tsx:73,265`）。

**影响**：网络失败、权限错误或服务异常时，会提示尚未配置服务/接口/场景，误导用户重复创建或误判数据丢失。建议显示明确错误及重试；保留已有缓存时标明数据可能过期。

### P2-2 接口搜索提交后输入框可能无法继续编辑

**证据**：`frontend/src/pages/console/ApiCatalog/ApiToolbar.tsx:36` 给 `Input.Search` 传入 `value={keyword || undefined}`，但没有 `onChange`，仅在 `onSearch` 更新状态。首次搜索后 keyword 非空，输入框变成受控组件，而输入不更新 value。

**影响**：搜索一次后，用户可能无法正常修改关键词继续搜索，并存在受控/非受控切换警告。建议区分输入草稿与已提交关键词，或增加 `onChange` 并明确触发搜索的时机。需浏览器验证实际交互。

### P2-3 切换项目后旧接口详情可能残留

**证据**：`frontend/src/pages/console/ApiCatalog/index.tsx:51` 的 `selectedApiId` 没有随 `currentProjectId` 重置；`:71` 只处理模块。`ApiDetail.tsx:30` 按接口 ID 查询，不校验当前项目。

**影响**：先选项目 A 的接口再切到项目 B，右侧可能继续显示 A 的接口，而树和模块选项已属于 B；用户可能误认为正在操作 B。服务端鉴权仍然生效，此处不等同于越权。建议切换项目时清空选择和相关弹窗，并验证缓存加载时的过渡。

### P2-4 结构指纹对参数列表顺序敏感

**证据与验证**：`backend/app/features/api_catalog/services/hash.py:22` 对字典键排序，但不对列表排序；本次用相同两个参数交换列表顺序调用 `compute_source_hash`，得到不同摘要。

**影响**：即使参数顺序没有改变接口语义，导入预览也可能显示 CHANGED；选择覆盖时会更新并增加版本。是否将顺序视作结构的一部分需要产品约定；若无语义，应按位置、名称等稳定排序，并考虑现有指纹迁移与兼容。

### P2-5 窄屏布局缺少适配

**证据**：截图页面采用固定 320px 左栏及 `wrap={false}`（`frontend/src/pages/console/ApiCatalog/index.tsx:129`），右侧还有多列详情和工具条；CSS 的窄屏规则仅调整模块标题（`ApiCatalog.css`）。

**影响**：窄屏时右侧可用空间明显不足、文字拥挤或需要横向滚动。建议在小视口切换为可折叠树/上下布局，验证 375、768、1440px 和键盘访问。此项为代码推断，未进行浏览器视口实测。

### P3-1 重复数据加载与大数据量性能风险

接口树每次筛选请求首页，再并发请求全部余页并在前端构造整棵树（`frontend/src/pages/console/ApiCatalog/ModuleTree.tsx:55`）；多个页面又各自实现有限首屏接口选择。接口规模增大时请求数、渲染量和失败概率会增长。建议统一可搜索分页选择器，并让树按模块或节点按需加载；同时检查筛选下模块计数是否应显示匹配数量。

### P3-2 文档和测试入口存在维护冗余

根 `README.md` 仍以「阶段一 / 52 个测试 / 多项未接入」描述，与现有任务、安全测试、Mock 和 Web UI 目录及当前测试规模不一致。`frontend/src/pages/console/ApiCatalog/index.tsx:9` 仍将 Mock 服务列为未接入，而项目已有 Mock 管理。建议按现状更新能力清单，并明确哪些是历史阶段记录。

不带目录执行 `pytest --collect-only` 时还会收集 `app/features/agent/nodes/test_*.py` 中 3 个业务节点函数；应在 pytest 配置限定 `testpaths = tests` 或明确统一执行 `pytest tests/`，避免将业务代码当测试。此项为收集结果，不代表运行失败。

## 全项目补充扫描：跨模块发现

以下为对其余功能域的补充，优先级与前文一致；除注明测试验证外，影响根据代码路径推导，未在真实数据库和浏览器中重现。

### P1-4 测试资产、套件和计划只加载前 100 条

`frontend/src/api/testManagement.ts:60` 为策略、测试点、测试用例、套件和计划默认请求第 1 页 100 条，接口返回裸数组，前端无总数。资产树 `TestManagement/TestAsset.tsx:122`、套件 `TestSuites.tsx:66`、计划 `TestPlans.tsx:68` 和执行中心 `ExecutionCenter.tsx:51` 未请求下一页。超过 100 条后对应资产、套件或计划不可见；执行中心也无法选择后续计划。任务链接定位用例还依赖首页数据（`TestAsset.tsx:148`），可能无法打开第 101 条以后的用例。建议后端提供分页总数，前端增加服务端分页或树按节点加载，深链接按 ID 直接读取。

### P1-5 安全概览的指标可能低估，失败也可能显示为零

`frontend/src/pages/console/SecurityTesting/index.tsx:85` 只取前 100 条安全用例、待处理问题及策略；`:123` 从这些部分数据计算覆盖接口、高危问题和启用策略数，但页面按完整统计展示。任一查询失败后没有错误分支，空数组或 0 会替代结果。项目超过 100 条时低估风险和覆盖；接口失败时也可能误以为没有问题。建议服务端提供项目级聚合，并显示每个指标的失败状态，不用局部数据冒充全量统计。

### P1-6 业务流程中的 API 动作未接收 Mock 运行上下文头

`backend/app/features/test_management/executors/test_case_executor.py:281` 将 `extra_headers` 放在 `__web_headers` 中，供 Web 绑定读取；业务流程的 API 动作在 `business/executors/business_flow_executor.py:393` 只合并环境头和映射头，并未取该变量。若流程测试依赖由执行框架注入的 Mock 上下文，API 动作可能无法命中该次执行指定场景，进而得到错误响应或执行失败。Web 动作有独立读取路径（`web_ui/runtime/adapter.py:166`）。建议统一传递并定义覆盖优先级，添加 API / Web 混合流程和并发隔离回归测试。此项尚未端到端复现。

### P1-7 安全用例、疑似问题和策略列表只显示前 100 条

`SecurityTesting/CasesTab.tsx:70,244`、`FindingsTab.tsx:55,157`、`StrategyTab.tsx:80,237` 都只取首页且关闭分页。安全用例的接口筛选项还从已加载的用例派生，无法用它找回首页以外的接口。策略关键词仅对首页本地过滤。影响后续安全用例的执行、问题处理和策略维护；需要服务端分页与筛选。前文代码中概览注释称列表各自分页，但实际这些列表没有分页入口。

### P2-6 业务管理的域、流程和规则被截断，失败也可能伪装为空

`BusinessManagement/DomainTree.tsx:36` 的业务域和每个域流程均只取首页 100 条；`RulePanel.tsx:33` 的规则同样如此且表格无分页。域与流程读取失败没有单独错误界面，可能显示为空，规则失败显示「暂无业务规则」。超过上限无法通过这些入口管理后续数据。域搜索虽为服务端搜索，但不能解决某域下流程以及规则的分页缺失。建议分页、增加失败和重试状态。

### P2-7 统一任务列表只展示首页 100 条

`Tasks/index.tsx:90` 固定请求首页 100 条；表格 `:119` 的分页只对已返回的 100 条做客户端分页，并非后端翻页。任务更多时页面看似可翻页，仍无法查看更早的后续任务。建议将页码、每页数量和返回 total 接入服务端查询；独立测试实时刷新时翻页与状态保持。

### P2-8 测试数据和通知渠道管理存在截断与错误态问题

`TestData/ProviderTab.tsx:43,110` 只展示前 200 个 Provider；`TestData/ProviderConfigDatabase.tsx:49` 只提供前 200 个数据库连接。`NotificationChannels/index.tsx:232,429` 只展示前 100 个渠道、无分页，查询失败还显示「尚未配置」。报告发送渠道选择也只取前 100 个（`Reports/ReportDetail.tsx:309`）。数据超过上限时无法管理或选择后续项；建议分页及服务端搜索，渠道查询失败单独展示并重试。

### P2-9 Web 页面对象和登录态列表存在截断

`frontend/src/api/webUI.ts:30,52` 页面对象使用后端默认的首页 200 条，登录态固定首页 50 条；`WebUI/index.tsx:47,115` 的表格只对这些已取回的数据做客户端分页，没有传入后端 total 与翻页。后续对象或登录态不能在该页面管理，也不能作为编辑用例的候选。建议分别接入服务端分页，选择器提供搜索及按 ID 回显。

### P2-10 报告列表在项目从无到有切换时违反 React Hooks 顺序

`Reports/ReportList.tsx:70` 在没有当前项目时提前返回，`:82` 才调用 `useMemo`。同一组件实例从无项目切换为选中项目时，Hook 数量发生变化，可能抛出渲染错误并导致页面不可用。建议将所有 Hook 移到条件返回前，或按项目拆分组件；应在浏览器中验证进入报告页后首次选项目的场景。

### P2-11 多个项目 / 模型 / 安全扫描选择器有首屏上限

管理后台的环境项目选择器只取 200 项（`admin/Environments.tsx:54`）；Agent 配置的模型选择器只取 100 项（`admin/AgentGovernance.tsx:92`）；缺陷项目及处理人分别只取 100 项和 200 项（`Defects/index.tsx:133`）；安全计划候选接口、基线用例和策略只取 100 项（`SecurityTesting/CasesTab.tsx:306`）；ZAP 创建向导的目标和策略、结果任务选择器只取首页 100 项（`SecurityTesting/zap/wizard.tsx:64`、`zap/results.tsx:35`）。超过上限后只能选择已加载项；应统一采用远程搜索及分页，避免看似完整的下拉。

### P2-12 计划和套件读取失败可能显示空态

`TestManagement/TestPlans.tsx:210` 与 `TestSuites.tsx:209` 区分加载和空列表，但未检查各自主列表的错误，失败后可能显示「暂无测试计划 / 套件」。执行中心 `ExecutionCenter.tsx:133` 已有错误分支，可作为统一处理的参考。
