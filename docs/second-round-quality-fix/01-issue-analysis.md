## 验收期间新增发现

完整 PostgreSQL/后端/E2E 验收在初始化阶段发现 Alembic 历史图冲突：`0082_api_response_keys.py` 与 `0082_automation_jenkins_provider.py` 都声明 `revision = "0082"`，而 `0083`/`0084` 继续沿其中一条链前进。Alembic 将当前 heads 解析为 `0082`、`0084`，导致 `upgrade head` 直接报 `MultipleHeads`，尚未进入全新数据库完整升级或 Playwright 浏览器阶段。

用户明确要求不得随意修改已发布迁移。本轮保留两份 `0082` 和其它历史迁移原样，只修复当前目标 `0084` 并按明确 revision 做真实 PostgreSQL/SQLite 迁移测试。修复 revision 冲突需要单独评估已部署数据库对同名 `0082` 的实际解释和兼容策略，不能在本轮静默重写历史。

## 现有安全保护（保留并验证）

- `ModelDiagnosticInput` 要求正整数 `project_id` 且 `confirm_model_call=true`；模型调用仍由明确按钮触发。
- 后端先校验项目编辑权限，再校验模型对项目可用；ASR/说话人音频必须属于请求项目，失败按不可见资源返回。
- 诊断结果只保存脱敏摘要，查询时再次检查项目权限。
- 本轮不改变现有 API 请求/响应契约，不重写模型适配器或迁移历史。
