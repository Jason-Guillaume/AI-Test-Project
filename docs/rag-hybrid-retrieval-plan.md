# 项目知识库混合检索优化方案

目标是让项目搜索、Agent 规划和用例生成都能找到措辞不同但含义相同的资料，同时保留接口路径、字段名、错误码等精确匹配能力。模型由管理员配置，项目按用途选择；更换受支持协议下的模型无需修改业务代码。本文是实施方案，效果以项目评测为准。

## 一、让模型可替换

- 在现有模型管理 API 和管理界面增加能力类型及协议选择。已有配置迁移为文本生成能力，保持已有生成任务的默认模型、候选列表和备用路由行为。embedding 与 rerank 分别选择，后者可关闭。
- 项目检索配置保存 embedding 配置引用、可选 rerank 配置引用、向量维度和距离度量、两路候选数、重排窗口、最终返回数及超时预算。首次未配置时继续 BM25。模型名称、供应商地址、密钥、输出维度均由配置解析；生产代码、迁移、前端选项及环境兜底禁止暗含某款具体模型。
- 通过协议适配器分别提供文档编码、查询编码、候选重排。适配器处理批量限制、文档与查询输入模式、响应维度校验和重排结果位置映射。运行时按能力、启用状态及既有授权选择配置。管理端按能力验证连接；聊天接口探活不能证明检索能力可用。
- 截图中的 Qwen-Embedding 与 Qwen-Rerank 可作为首轮管理员选项。它们只是部署示例。模型兼容既有协议时，修改配置即可；服务商采用新协议时，只扩展相应适配器。

## 二、建立可演进的向量索引

1. 首版沿用已有 chunk_id、文档版本和页码，使用 PostgreSQL 与 pgvector。为每代索引记录不可变的编码配置，包括模型及服务端版本或人工指定的版本标记、文档和查询编码规则、维度与距离度量。密钥轮换与超时调整独立于编码版本。
2. 保存可支持不同维度的向量，例如使用无固定维度的 vector 列，写入时按索引代校验维度，查询只比较同一代。首版先做授权范围内的精确搜索。若实测需要近似索引，再为指定索引代及维度建适配的索引，比较过滤后的召回率与延迟。
3. 解析完成时，在保存文本片段的事务内登记持久化索引任务。后台分批领取任务，在事务外调用模型，再按“索引代 + chunk_id”幂等写入。记录进度、限次重试和失败原因；进程重启可以续跑。存量文档从已有片段回填，无需再次上传。并发删除、停用和版本更新按现有知识生命周期复核。
4. 更换 embedding 模型、维度或编码规则时，创建新索引代并在后台回填。切换前处理回填期间新增的片段，核对可检索版本的覆盖率，通过抽样评测后原子切换查询模型与索引。旧代在回滚窗口内保持可查询并追平增量。即使新旧维度相同，也分别检索各自的向量空间。更换 rerank 模型独立生效，无需重算文档向量。

## 三、接入真实检索路径

1. 在公共 search 入口沿用当前项目、Agent 绑定、文档启停及冻结版本的授权检查。limit=0 只复核权限；空查询保留现有浏览行为。实际查询在授权且有可读版本时才调用模型。缓存如用于复用同一任务的查询向量，键包含编码版本和查询内容；每次读取候选仍按当前权限校验。
2. 关键词和向量两路各自在授权版本内取候选。向量路径独立搜索，可找到没有词面重合的相关片段。两路按 chunk_id 去重并以 RRF 融合，再从融合结果选候选原文重排。首轮可试两路各取 50 条、融合后 30 条重排、最终返回 8 条；这些数值仅为评测起点。保留请求的 top_k 语义，窗口至少覆盖请求数。
3. 向量未就绪、超时或无有效候选时直接返回 BM25 排名。修正当前传入空候选列表也进入 RRF 的行为。重排超时或响应索引无效时返回融合排名。保留旧调用方的 BM25 阈值语义，按评分类型单独定义融合和重排阈值。审计事件按实际执行策略记录，响应保持原有片段、版本、页码与位置。
4. 针对泛化标题，规划查询拼入可用的需求摘要。已按模块拆分的用例生成任务可用“模块 + 对应需求”检索，保留接口和字段原文。分别测量查询改写与向量召回的增益。若频繁出现条件和例外被切开的情况，再试按标题、段落或列表切分，保留来源定位并版本化切片规则。

## 四、验证与发布

| 场景 | 验收方法 |
| --- | --- |
| 检索效果 | 同一批真实问题标注正确文档及原文位置，包含同义改写、错误码、跨段规则、长需求和无答案问题。分别对照 BM25、双路融合、融合加重排，记录候选 Recall@30、最终 Hit@8、MRR、无关命中和端到端 P95。按项目延迟预算及业务样本选择上线策略 |
| 可替换性 | 用两个测试配置（含同维度和异维度用例）完成索引回填、切换和回滚；验证同维度跨模型也不会混查。仅换 rerank 时，文档 embedding 调用数应为零 |
| 权限与兼容 | 覆盖项目搜索、Agent 搜索和生成任务。校验跨项目、撤权、停用、已删除及任务冻结版本场景；无权文本不得进入远端重排请求。老项目无检索模型配置时仍可使用原有搜索 |
| 恢复与观测 | 模拟限流、超时、重复任务、worker 重启、回填期间上传新版。按检索策略和索引代记录覆盖率、两路候选数、各阶段耗时及降级原因，日志不记录凭据和业务原文 |
| 集成验证 | 离线测试使用可替换的假模型服务，校验请求和排序；在启用 pgvector 的 PostgreSQL 上验证迁移、维度隔离和检索。真实模型质量用已配置端点另测，单独报告实测和未验证项 |

交付顺序为基线评测 → 配置管理与异步入库 → 单项目双路召回 → 可选重排 → 模型切换和回滚演练。每步保持可独立验证；上线先限于试点项目，保留切回 BM25 的项目级开关。
