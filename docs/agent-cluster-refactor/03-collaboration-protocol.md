## 任务与智能体如何交互

### 主流程

1. 用户从全局抽屉或管理页面创建 Task，指定项目、目标、环境、选中资源和文件引用。
2. 创建 TaskRun，并创建任务主 Agent 会话。缺少目标、环境或资源时进入待补充状态。
3. Planner 产出结构化方案。服务端校验资源范围、工具可用性、角色权限、依赖无环、并发与预算。
4. 展示可编辑方案。已有业务确认要求继续作为独立审批对象；任何方案变化均形成新版本。
5. 调度器创建所需参与者并领取可执行 WorkItem。不存在前置依赖的 API 与 UI 子任务可以并行。
6. Worker 接收目标和上下文，通过已注册工具执行；持续记录可展示的行动摘要、调用结果和业务产物引用。
7. 结果按输出契约校验后被接受；下游读取已接受的版本。审阅不通过时记录返工原因，限额内生成新尝试或子任务。
8. 报告 Agent 汇总通过、失败和未执行项。主 Agent 给出最终说明与业务页面链接。

LLM 负责理解、规划和提出动作；服务端调度器负责状态、锁、依赖与配额。LLM 输出“已完成”不能直接令任务成功。

### 消息路由

- 任务级消息发给任务主 Agent，用于修改目标、范围和执行要求。
- 角色级消息明确指定参与者，由服务端写入该会话邮箱，Worker 在下一可处理边界消费；已接收与已处理分别展示。
- Worker 的澄清问题上报主 Agent，需要用户回答时关联到原子任务，收到答案后继续调度。
- Worker 请求协作时提交结构化协作请求，由主 Agent 协调、调度器验证后创建允许的实例。不能不受限地递归创建智能体。
- 暂停、取消、批准和重试使用显式命令端点；聊天文字不会伪造成已有业务审批记录。
- 系统事件、工具调用和参与者消息分别持久化，前端可按时间合并展示。消息角色由服务端确定。

### 计划调整

用户修改任务时，主 Agent 生成变更摘要：新增/取消子任务、已完成结果是否复用、额外预算及需要重新确认的操作。先停止旧版本的新派发，再让运行段在安全边界结束，发布新版本并使受影响下游结果失效。历史事件与产物保留，不能原地覆盖造成串用。

### 业务页面衔接

| 页面 | 智能任务入口 | 任务产物回链 |
|---|---|---|
| 接口管理 | 选中接口 → 生成测试/执行回归 | 接口、测试点、用例、执行记录 |
| 业务管理 | 选中流程 → 验证业务链路 | 流程执行与步骤结果 |
| 测试资产/套件/计划 | 选中资产 → 生成、审阅、执行或分析 | 原有资产详情及来源任务 |
| Web UI 自动化 | 选中页面对象或用例 → 创建 UI 任务 | 用例、截图、Trace、执行记录 |
| 安全测试 | 选中目标和策略 → 拟定扫描方案 | 原有扫描任务、Finding、审批记录 |
| 报告与缺陷 | 选中结果 → 汇总、分析或形成缺陷草稿 | 原有报告/缺陷详情与证据 |

任务输入记录资产 ID、版本/摘要和有效配置快照。资产修改不悄悄改变在跑任务；执行前再次验证存在性、权限及既有确认指纹。内容变动后按工具约定重新规划或重新确认。
