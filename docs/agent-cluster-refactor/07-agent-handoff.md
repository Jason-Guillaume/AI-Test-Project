## 可直接使用的重构指令

请在当前 `ai-test-project` 代码库中实施“任务与多职责智能体集群”重构。目标是在保留现有接口管理、业务流程、测试资产、测试计划、执行中心、报告、Web UI、安全测试、Fixture / Mock 和权限体系的前提下，增加统一任务与智能体协作层。以本目录 README 和 01–06 文档为实施依据；先阅读仓库编码规范、项目开发指引，并核对当前代码、已有改动、真实迁移 head 和测试入口，记录与设计基线的差异。

平台必须区分全局助手与任务内团队：全局助手通过右侧抽屉创建、查询、跟踪任务；每个任务运行拥有独立的任务主 Agent、Planner、按需创建的 API / UI / 安全 Worker，以及质量审阅和报告角色。Agent 是可复用模板，Worker 是某次任务中的运行实例。各实例拥有独立会话、职责、模型绑定、Skills、工具白名单和输入/产物引用，禁止不同任务共享可变上下文。首个真实组合为主 Agent、Planner、API Worker 和报告 Agent，其他职责按阶段接入，不强制每个简单任务启动所有角色。

交互上增加全局任务列表和任务详情。详情左侧展示任务主 Agent、Planner、系统事件及 Workers，右侧按所选参与者展示独立消息、执行摘要、可展开工具调用、状态、模型用量和产物。用户既可向主 Agent 调整整体目标，也可向指定 Worker 补充要求；接收对象、消息已接收/已处理状态必须明确。系统事件是实际审计记录，不伪装成智能体。全局抽屉跨页面保留会话，关闭抽屉和刷新页面均不影响后台任务执行。原有管理页支持选择资产发起任务，任务产物能打开原来的用例、计划、执行或报告详情，并能反查来源任务。

后端使用持久化的 Task / TaskRun、编排方案、子任务依赖、角色实例、执行尝试、消息、命令、事件和资源引用组织执行。LLM 负责理解、规划与提出动作；服务端调度器负责权限、依赖、状态转换、领取、并发、心跳、预算和重试。长任务提交后立即返回，不在 HTTP 消息请求中同步跑完整任务。第一阶段沿用现有技术栈，以 PostgreSQL 支撑调度与游标事件查询，不为该重构预先引入额外智能体框架或消息中间件。

Worker 必须通过可校验的工具契约复用现有业务服务和执行器，真实产物仍写入原业务模块。对创建计划、保存用例、启动执行等副作用建立幂等键和可查询回执。暂停/取消在安全边界生效并展示中间状态；进程中断后按能力查询回执或恢复，结果不明时进入待核对，禁止盲目重放。浏览器会话需要明确 owner 与资源上限，不能宣称恢复丢失的活句柄。保留已有 Web、扫描和通知确认机制；AI 审阅不能代替人工批准。权限与项目出站限制以服务端为准，密钥、JWT、登录态不进入模型上下文和普通日志。

新增 Agent、Skill、Tool / MCP 与模型职责绑定的配置入口，复用现有模型和密钥配置，按现有权限开放。支持“自然语言描述 → AI 起草 → 编辑 → 校验 → 保存草稿 → 发布版本”，运行采用固定配置版本。AI 起草工具定义不代表工具已经具备执行能力；必须有真实适配器或已接入服务。文件支持受控上传、后台解析、状态反馈、按来源片段引用及项目/任务隔离，按阶段增加格式，失败明确显示，不把大文件无条件塞给所有 Worker。

按 05 文档的 P0–P6 分阶段实施，先形成 P0–P3 的可用闭环，再扩展后续阶段。每阶段完成代码、必要迁移、前后端契约、对应测试和交付记录后继续推进。若执行时间或上下文不足，在可恢复节点留下精确的进度与下一步；不能把部分交付宣称为整体完成。最终交付应覆盖真实的多角色协作、管理页衔接、事件恢复、幂等、权限和兼容回归。不要只交新页面、空壳调度器或测试替身。未经真实模型/环境验证的外部能力明确标记为未验证，测试替身仅用于确定性测试。

在授权的重构范围内自主推进实现、定向验证和常规问题修复；先给出简短实施顺序，随后开始落地，不停留于再次制定计划。遵守仓库分支与提交规范，保留已有未提交改动，不执行破坏性数据库初始化、不写入密钥、不擅自上线或删除旧功能。若遇到影响范围、权限或不可逆数据操作的实质问题，先完成独立可推进的部分，再说明具体阻塞与所需决定。

## 每阶段交付记录格式

1. 阶段与覆盖需求：列出本次完成的 P 阶段及文档条目。
2. 实现内容：受影响模块、重要契约、迁移与兼容行为。
3. 验证证据：实际执行的命令、结果、关键浏览器流程；区分真实集成与测试替身。
4. 未完成与限制：具体能力、失败原因、是否影响阶段出口。
5. 后续工作：下一可执行任务、依赖和恢复入口。

## 最低完成判定

- 两条任务并存时，角色会话、文件、资源引用和执行结果不串用。
- 任务运行有真实 Planner 与 Worker 交接，而不是一个调用链配多个显示名称。
- 页面关闭、网络重试、事件重连和安全边界暂停/取消不造成任务丢失或重复业务副作用。
- 通过原有业务服务产生可打开、可追溯的资产、执行记录及报告。
- 原有管理页、权限、确认、出站策略与执行链通过相关回归。
- 配置与文件能力按阶段真实接入，未完成、未知用量和未验证外部能力如实呈现。
