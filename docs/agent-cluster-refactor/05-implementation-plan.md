## 分阶段实施与验收

按依赖顺序推进；以阶段出口验收，不在未实测前承诺开发天数。

| 阶段 | 实施内容 | 阶段出口 |
|---|---|---|
| P0：契约与边界 | 固定概念、职责、任务状态机、消息接收规则、权限、工具幂等和兼容协议；补充模块改造清单 | 一条订单回归样例可明确指出每步由谁负责、产物写在哪里、失败如何处理 |
| P1：任务运行底座 | Task / Run / WorkItem / Instance / Attempt、命令、事件、资产引用；数据库领取、并发、心跳、检查点；最小任务查询界面 | 离开页面继续运行；刷新恢复；同一工作项无双重领取；暂停/取消/重试可追踪 |
| P2：任务内团队与 API 链路 | 版本化固定 Agent 模板；主 Agent、Planner、API Worker、报告 Agent；独立会话、模型显式绑定；原执行链适配、已有确认接入；基础文本附件 | 一个任务内有真实职责与会话，通过现有服务产生用例、执行记录和报告，重试不重复写入 |
| P3：任务产品界面 | 全局任务列表、截图式参与者会话布局、任务方案与产物、全局抽屉、管理页选中资产入口和来源回链 | 两条任务同时存在时消息与上下文不串用；从管理页发起并能从产物回到管理页 |
| P4：UI / 安全能力和审阅协作 | 接入正式 Web 用例与交互式编写的不同适配器；浏览器资源归属；接入既有 ZAP 队列；质量审阅与有限返工；依赖汇总 | API 与 UI 可并行并受配额控制；报告等待必需产物；已有人工确认与出站限制全部保留 |
| P5：配置与文件扩展 | Agent / Skill / Tool 草稿、版本发布与绑定；AI 起草；模型职责绑定界面；PDF/DOCX/XLSX/图片等解析；后续 MCP/HTTP 接入 | 新模板可被新任务选择；修改不影响已在跑版本；自定义工具只能调用真实接入能力；文件可定位引用 |
| P6：兼容迁移与运行加固 | 特性开关、旧会话适配、历史来源链接、可观测性、配额压测、部署与回滚演练 | 旧管理页及旧执行链回归通过；新路径可灰度、可停止新派发并切回旧入口 |

首个可用版本范围是 P0–P3，以固定职责组合跑通真实 API 测试和报告；UI/安全与动态配置分别按 P4/P5 增量接入。P1 中的测试执行器替身仅用于验证运行机制，不能作为产品已接入的证明。

## 实施拆分与建议交付顺序

1. 任务契约、基础迁移和创建/查询服务。
2. 持久化调度、配额、心跳、暂停/取消及中断状态处理。
3. 参与者会话、消息邮箱、事件查询与命令去重。
4. Agent 模板快照、显式模型选择和任务内主 Agent / Planner。
5. API Worker 的查询、生成、执行适配与业务回执幂等。
6. 报告 Agent 和产物关联，形成第一个后台完整闭环。
7. 任务列表、参与者执行台与全局抽屉；业务页面发起与回链。
8. 正式 Web 用例、交互式浏览器、安全扫描及资源调度适配。
9. 质量审阅、有限返工、并行冲突和共享测试数据的隔离。
10. 配置中心、文件格式扩展、MCP/HTTP 与迁移加固。

每批提交包含对应迁移、服务/页面、中文注释、契约与定向测试，不把全部内容合成一次大替换。实施时遵守仓库功能分支和迁移规范；本条说明针对文档编制阶段；接收 07 中的实施指令后，应按已授权范围执行实际重构和验证。
