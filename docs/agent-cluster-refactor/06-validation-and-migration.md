## 验证计划

### 运行与协作

- 并发领取同一子任务只有一个有效所有者；全局与项目资源额度不会因竞争而超限。
- 重复创建命令、重复确认和网络重试不产生重复业务资源或执行记录。
- 任务 A 的消息、文件、Worker 结果不能进入任务 B；同角色多实例的接收对象明确。
- 主 Agent / Planner 的方案必须通过依赖无环、角色、预算和工具授权校验。
- 暂停期间不派发新工作；取消与执行完成竞争时状态一致；迟到结果不能覆盖新尝试。
- 上游失败、可选项失败、审阅返工和预算耗尽得到明确终态与报告说明。

### 恢复与业务副作用

- 在“创建业务记录前、创建后未回执、执行中、结果回写前”分别模拟进程中断。
- 可查询回执的业务动作被重新关联；状态不明的操作进入待核对，不重复执行。
- 浏览器句柄丢失、资源耗尽、模型不可用与模型超时均有可读原因，不伪造恢复成功。
- 并行 API / UI 使用共享账号、Fixture 或测试数据时，按资源锁或独立数据分配策略验证隔离。

### 权限与既有能力

- 跨项目任务、消息、文件、资源引用和工具调用均拒绝；发起者被停用或移除权限后停止新的受限操作。
- 新配置版本不会隐式改变在跑任务的模型/Skill/Tool 与执行范围。
- Web 用例/步骤、扫描和通知仍通过既有确认，AI 审阅不能伪造批准。
- 复用原有 Agent、Web 和 ZAP 定向测试，新增关键任务运行与工具幂等回归。
- 原接口、业务流程、测试资产、执行、报告、Fixture/Mock 和组织/项目切换保持兼容。

### 前端与迁移

- 创建任务 → 查看不同角色 → 指定接收者补充要求 → 暂停/恢复 → 打开业务产物。
- 切路由保留抽屉会话；切项目不改变任务归属；登出后清除订阅与会话缓存。
- 游标补拉、事件重复、断线续读、终态校准和未知用量呈现均验证。
- 配置页草稿、AI 起草、校验、版本发布、停用与旧任务读取分别验证。
- 新迁移从实际 head 追加，在隔离库验证空库升级、已有库升级、seed 幂等与阶段回退；更新全部 head 断言。
- 运行受影响的后端测试、前端类型检查与构建，阶段出口增加完整回归及关键浏览器流程。

本轮为计划编制，未运行上述测试；以上为实施后的验收要求。

## 兼容、灰度与回滚

- 新增任务入口通过特性开关和项目试点逐步启用，旧会话、旧执行与管理页继续可用。
- 旧 AgentSession 可以作为新任务的来源引用，或通过明确适配器作为一个子流程执行；一个会话只能有一个推进所有者，禁止新调度器与旧消息 API 同时推进。
- 不把历史对话伪造成过去已经存在的多智能体运行记录。需要迁移时保留原时间、原权限及来源关系。
- 通用任务层只调用既有 ZAP 任务服务，并收集它的状态；扫描仍由原扫描 Worker 领取执行。
- 模型配置、Skill 和工具版本停用时保留历史快照。凭据撤销与出站授权仍按当前策略生效。
- 回滚先禁止新运行与新派发，处理运行中任务与资源释放，再关闭新入口；业务产物仍可从原管理页面访问。
- 优先使用向后兼容的新增表/字段。运行记录需要审计时不直接降库删表；结构回退另行演练。
