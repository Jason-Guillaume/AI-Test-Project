## 1. 目标、范围与完成定义

让用户围绕“提出目标 → 确认范围与方案 → 查看执行 → 处理结果”完成测试，不必先理解 Agent 角色、调度工作项和所有业务模块。保持现有 React、TypeScript、Ant Design、React Query 和 FastAPI 技术体系。

本轮必须完成 A–D 四阶段：交互修复、前端简化、待处理中心和任务模板、运行对比和失败闭环。阶段是实施顺序，不是默认暂停点。完成一阶段后继续下一阶段；确有外部阻塞时记录并推进不依赖该阻塞的部分。

以下作为后续路线，本轮不开发：API 变更影响分析、定时/CI 触发、Agent 全面替换或执行引擎重写、全站视觉翻新。不要为本方案另起新网站。

完成意味着前后端接口、持久化、权限、交互和必要验证均到位，不能用静态演示数据、占位按钮或只有表单没有服务端的方式交付。

## 3. 页面与信息架构

### 3.1 导航映射

一级入口控制在六组，嵌套分组默认仅展开当前所在组；菜单可折叠且记忆用户选择。管理入口按现有权限展示。

| 一级入口 | 主要内容 | 兼容方式 |
| --- | --- | --- |
| 工作台 | 最近任务、待我处理、创建任务 | 沿用 `/console` |
| 任务 | 任务列表、AI 助手、任务模板 | 保留 `/console/tasks`、`/console/agent` 及详情深链接 |
| 资产 | 接口、业务、用例、套件、测试计划、Web、安全、数据、Mock | 原专业页面作为二级入口，保留原地址 |
| 结果 | 执行历史、报告、缺陷 | 保留报告和执行详情链接；执行中心保留可访问入口，主导航中并入任务相关操作 |
| 项目设置 | 项目管理、通知渠道 | 原页面与权限逻辑不变 |
| 管理 | 原管理端 | 仅符合权限的用户可见；不复制管理页面 |

消息中心放在顶栏，个人中心放在用户菜单；原地址继续可访问。不得通过删除页面或隐藏原功能来实现“简洁”。面包屑、选中态、返回行为与新导航保持一致。

### 3.2 用户默认看到什么

- 工作台：一个显著的“创建任务”入口，最近任务与待处理列表，少量真实状态指标。
- 任务详情：顶部展示任务目标、当前状态、环境、阻塞原因和下一步；主要区域是对话、方案摘要和结果；Agent 参与者、工具审计、工作项和原始事件进入“高级详情”。
- AI 助手：保留会话历史入口，对话为主，右侧结果可收起；审核结果与确认操作放在一起。API 资产生成与任务执行必须通过真实资产/任务引用串联。
- 专业资产页：保留直接编辑、调试与筛选能力；创建任务时带入当前项目、类型和选中的资产，执行环境仍需明确确认。

### 3.3 视觉与交互规则

- 使用现有主题 token，统一间距、圆角、状态色与中文状态映射；主内容建议 14px，辅助信息不低于 12px。无需更换组件库或加入装饰性大图。
- 计划默认呈现目标、范围、环境、步骤和验收条件；结果默认呈现通过/失败数量、失败原因、证据和下一步。不存在的指标显示未知，不伪造为 0。
- JSON 只在“原始数据”详情中展示，维持服务端已有脱敏边界，不扩大敏感数据暴露。
- 支持加载、空、失败、无权限、处理中和部分成功等真实状态；需要用户动作时给出具体入口，避免仅用 toast。
- 图标按钮有可访问名称，焦点清晰，可用键盘完成创建、审核和错误重试；重要状态不能只靠颜色区分。
- 1440px 展示对话加结果栏，会话列表可收起；1024px 优先保证对话可读，结果栏按需展开；768/390px 使用单栏和面板切换，审核按钮固定在当前结果面板内。以容器实际宽度校准，不盲目按视口硬编码。
- 页面主体无横向溢出；长表格和代码块可局部滚动。长标题截断后可查看全文；小屏不让固定栏遮挡最后一条内容或输入框。

## 4. 阶段 A：修复交互正确性

### A1. 选择与确认契约

- 审核列表提供全选、取消全选、部分选择和准确计数；初始选择明确展示，不允许界面 0 条而服务端按全部执行。
- 新前端确认必须发送显式非空 ID 列表；后端区分 `None` 与 `[]`，显式空数组拒绝，不能使用 `ids or all_ids` 混淆语义。
- 为兼容旧客户端，缺省列表是否保留“全部”需核对既有调用；若保留，只限明确的旧契约，并记录兼容行为与测试。新 UI 不依赖缺省全部。
- 执行严格使用已确认范围；执行弹窗展示实际数量、范围与环境。不能因为零选或状态丢失扩大范围。
- 校验 ID 属于当前项目、会话和可操作资产，客户端禁用不能替代服务端校验。

### A2. 项目、会话和异步响应隔离

- 切项目立即解除旧会话及其工作区、选择项、消息快照；新项目准备好前禁用发送和审核。
- 切会话清理选择项，草稿按会话保存或明确清空，不把上一会话内容带入另一会话。
- 请求发出时捕获项目/会话身份，迟到响应只更新原对象的缓存，不污染当前页面、不清除当前草稿；无效会话显示可恢复入口。
- 不以无差别重挂载整个控制台替代所有页面的作用域治理。

### A3. 消息与状态修复

- 失败发送保留原文和重试入口；成功后只清理此次发送的草稿。请求中防止重复提交。
- 使用正确的消息末尾锚点，仅在接近底部时自动滚动；阅读历史时显示“有新消息”。
- 会话列表、工作区、任务抽屉各自有错误态和重试；只有 execution_result 也能展示结果。
- 任务全局计数来自完整授权数据的服务端统计，不能拿第一页 100 条算总量；状态更新后失效相关缓存。

主要文件：`frontend/src/pages/console/Agent/*`、`frontend/src/widgets/task-assistant/TaskSchedulerDrawer.tsx`、`backend/app/agents/router.py`、`backend/app/agents/workflows/legacy/graph.py` 及对应 schema/service。

验收：零选/部分选/全选、执行范围、A→B 项目切换、会话切换中迟到响应、断网重试、只有执行结果、超过 100 条任务统计均有行为证据。

## 5. 阶段 B：简化现有前端

- 按第 3 节完成导航、工作台、任务详情和 Agent 页面，所有既有功能仍可到达。
- 复选框与结果卡片合并，确认/执行/重新生成操作就近呈现；明确一个主要动作，其他动作放次级区域。
- 创建任务默认聚焦目标、类型、环境和范围，项目沿用当前选择且可切换；Agent 选择、预算等进入高级设置。保持 API/Web 已确认用例、Web 编写和安全评估各自真实前提，不把自然语言输入当成已支持任意任务。
- 根据 target_type 启用相关查询。API 模式不读取 Web 登录态、安全策略和安全会话；打开高级设置不应导致无关领域全量加载。
- 可检索资产使用服务端搜索和分页，保持跨页选择与已选标签；若对应接口不支持搜索，扩展所属领域的现有查询接口，不能仅在已加载第一页做“全量搜索”。
- 状态映射放在适当领域公共位置，widgets 不反向依赖 pages；复用已有空态、错误态、时间格式和主题。
- 完成态停止无意义轮询；运行中沿用增量事件读取和合理轮询，暂不以新增 SSE/WebSocket 为前置条件。

## 6. 阶段 C：新增待处理中心与任务模板

### C1. 待我处理

- 工作台和任务入口展示待确认、模型配置阻塞、失败待处理、待核对四类；与“进行中”数量分开。
- 第一版“我的”限定为当前用户发起且当前仍可见的任务，不凭空引入不存在的负责人/审批人体系。若当前代码已有明确处理人分配，优先复用并说明规则。
- 项目过滤、分页、各类准确计数由服务端完成；使用最新运行的真实状态，不从旧通知数量推断待办。
- 每条显示项目、任务、运行、原因、时间、下一步；链接定位准确运行和对应操作。模型配置仅向有权限者提供编辑入口，其他用户看到明确阻塞说明。
- 处理完成、运行被替代或权限变化后及时移除，历史通知不因待办消失被删除。复用已有命令接口，不新增旁路执行接口。

### C2. 任务模板与再次执行

- 第一版为项目共享模板；读取与写入遵循项目现有权限体系。支持创建、编辑、停用/删除、列表搜索、从模板创建任务及从现有任务“再次执行”。
- 持久化名称、说明、目标、任务模式、资产引用、可选环境/Agent 引用、类型专属参数、版本和创建/更新时间。保存结构化配置，不复制运行 ID、状态、历史消息、密钥或浏览器临时会话。
- 编辑模板递增版本；创建任务记录使用的模板 ID/版本和实际输入快照，历史任务不受模板后续修改影响。
- 模板启用不等于资产可用。使用时重新校验项目权限、环境、Agent、资产状态和范围；失效引用逐项提示，要求修正后提交。
- 再次执行打开预填表单，用户确认后创建新任务；不复活旧运行。生成新的幂等键，重复提交不得创建重复任务。
- 安全评估和 Web 操作保留原有审批边界；临时 Web 会话和过期登录态不得盲目复用。
- 新表使用 Alembic 增量迁移，不修改初始迁移，不建立第二套 Task/TestRun 主表。

主要后端入口：`backend/app/orchestration/tasks/`；前端契约与 API：`frontend/src/features/tasks/`；相关新模板组件放所属领域或页面内。

验收：真实数据刷新后保留；越权读写被拒绝；失效资产不能提交；模板更新不改变旧快照；双击创建不重复；待办计数和列表相符。

## 7. 阶段 D：运行对比与失败处理闭环

### D1. 运行对比

- 从报告/执行历史选择两次执行，首版限同项目、同测试类型、有可对齐结果的两次业务执行；不把 TaskRun ID 与业务 TestRun ID 混用。
- 按稳定用例身份及必要的数据实例身份对齐，不能按数组下标或名字匹配。缺少稳定对应关系的条目标为无法比较。
- 展示新增失败、已恢复、持续失败、新增/移除用例、耗时差异；未执行或跳过不判为通过/修复。耗时缺失保留未知。
- 展示环境、时间和可用的资产版本差异；缺少版本快照时明确说明可比性有限，不伪造历史版本。
- 对比项能打开两次对应证据；分页/筛选与全量汇总一致。服务端同时校验两侧可见性，不同项目拒绝。

### D2. 失败到缺陷再到验证

- 在失败结果处提供“关联已有缺陷”“创建缺陷”和适用的重试入口；预填脱敏摘要、用例、执行、任务引用，用户确认后写入。
- 来源与缺陷双向可追溯，重复点击幂等；被删资源或无权限显示可理解的状态，不能静默跳到其他对象。
- 复用已存在的可重试工作项语义，不将工作项重试包装成只执行失败用例。
- “验证修复”创建引用原缺陷与用例的新任务，重新确认环境和范围；复用现有前置条件与数据准备逻辑。缺少依赖解析时提示并禁止不安全的部分执行，不能悄悄跳过依赖。
- 新执行结果回链到缺陷，显示通过/失败/无法判定；不自动关闭缺陷，不把安全疑似问题自动变成已确认漏洞。

主要领域：`backend/app/features/reports/`、`backend/app/features/defects/`、`backend/app/features/test_management/`、`backend/app/orchestration/tasks/` 及对应前端 features/pages。

验收：可比/不可比运行、缺失数据、跳过用例、跨项目拒绝、重复关联、失效资源、缺陷→验证任务→结果回链。
