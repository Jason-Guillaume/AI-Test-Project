# 缺陷导入与导出方案（第一版）

## 格式与适用人群

建议首版使用无宏 Excel 工作簿（.xlsx）完成导入、导出和模板下载。测试人员能在同一份文件里填写中文、多行步骤和接口数据，查看字段说明，并通过下拉选项填写分类与等级。将版本号、前导零和长编号写为文本，避免打开文件时被自动改成日期或数字。Google 表格可导入 Excel 文件，WPS 表格也支持 XLSX；下拉列表仅作录入辅助，最终校验统一在服务端完成。[Microsoft 格式说明](https://support.microsoft.com/en-us/excel/file-formats-that-are-supported-in-excel) · [WPS 格式说明](https://www.wps.com/office/spreadsheet/) · [Google 表格互操作说明](https://support.google.com/docs/answer/9331167?hl=en)

CSV 适合只有一张明细表、由脚本或第三方系统消费的场景。Excel 将 CSV 保存为当前工作表的文本和值，字段说明、下拉选项和文本类型都无法随文件传递。有明确对接需求时，再用相同的列定义增加 UTF-8 BOM CSV 导出，并单独验收引号、逗号、换行和公式样文本。[Microsoft 格式差异说明](https://support.microsoft.com/en-us/excel/excel-formatting-and-features-that-are-not-transferred-to-other-file-formats) · [Excel 与 UTF-8 CSV](https://support.microsoft.com/en-us/excel/opening-csv-utf-8-files-correctly-in-excel)

## 文件约定

模板包含「缺陷明细」「填写说明」两张表。明细首行固定中文表头，每行一个缺陷，按列名匹配，允许调换顺序。说明页标注模板版本、允许值和示例；示例放在说明页，避免误导入。首版只创建新缺陷。

| 列 | 导入约定 |
| --- | --- |
| 标题 | 必填，去首尾空格后 1–200 字。 |
| 前后端划分 | 可空；支持前端、前后端、接口，历史值「后端」映射为「接口」。 |
| 描述、复现步骤、预期结果、实际结果 | 可空，保留单元格内换行；长度按既有契约校验。 |
| 严重度、优先级 | 可空，接受 1–4 或对应中文标签。严重度 4 为「严重」，优先级 4 为「紧急」。空值沿用批量创建默认规则。 |
| 发现环境、影响版本 | 可空，按文本读取，例如 001.02。 |
| 请求方法、请求地址、请求头、请求体、实际响应结果 | 接口缺陷专用。填入这些字段但分类不匹配时，指出行号和冲突列，避免静默丢弃。 |
| 缺陷 ID、当前状态、报告人、创建时间、更新时间 | 仅用于导出查阅。含已有缺陷 ID 的行阻止作为新单导入，防止把导出文件误当成更新文件。需复制为新单时清除 ID，预览明确标注新建。系统字段不参与写入。 |

同一项目下标题允许重复，预览提示文件内相同标题和内容，由用户决定是否修改。选定的目标项目、当前登录人和既有队列规则决定归属、报告人和初始「待确认」状态。状态在导出中使用页面展示名，例如「待验证」。附件文件、活动历史、分享凭证不进入工作簿。默认导出常规事实字段；请求头、请求体和响应正文默认排除，启用接口详情导出时须采用经验证的脱敏规则并在文件说明中标记。

## 页面流程

1. **下载模板。** 缺陷管理工具栏提供「导入」「导出」。导入弹窗给出目标项目、空白模板和每次 1–100 条的限制，沿用现有批量创建上限。
2. **上传并预览。** 解析「缺陷明细」，跳过完全空白行，保留原始 Excel 行号。提示未知列，拒绝缺失或重复必需表头、重复映射、公式单元格及不支持的文件版本。展示待创建数和逐行错误，例如“第 7 行 · 优先级：请输入 1–4 或低、中、高、紧急”。存在错误时整批留在预览，用户修正后重新上传。
3. **确认导入。** 确认时再校验项目写权限。整批成功才创建缺陷、活动和通知，并返回批次编号和各行缺陷 ID。失败整体回滚。对同一预览的重试返回同一回执；重新上传相同文件时提示最近成功批次，由用户显式选择是否再次新建。
4. **导出。** 可选「当前项目的筛选结果（全部页）」或「已勾选缺陷」。显示目标项目、数量和字段范围；沿用列表的队列、日期、关键词、草稿及归档可见性。服务端按当前用户重新查询，勾选项已失效时提示刷新。零条时给出明确反馈。时间列注明时区；超出单元格可表示的长度时提示具体记录，避免无提示截断。

## 实现与验证

- 复用后端已有 openpyxl、测试用例 Excel 的上传预览交互，以及缺陷 BugBatchItem 字段契约。建议在缺陷路由新增模板下载、导入预览、确认和导出四个入口，静态路径注册在动态缺陷 ID 路由之前。导出从列表的权限及筛选查询分批读取，避免前端翻页拼文件。
- 现有 batch_create_bugs 自行提交事务。实施时抽出可在调用方事务中执行的建单逻辑，让导入回执、活动和缺陷同事务提交；保留原批量创建 API 的提交行为。预览标识绑定用户、项目、标准化数据摘要和有效期，确认时用唯一约束防止重复并发提交。
- 服务端校验文件内容、压缩和解压后尺寸、工作表范围与行数，再读入数据。导出用户文本时显式写字符串，即使标题以等号开头也应显示原文。压测后设置导出行数上限，超限时提示收窄筛选，避免静默导出部分结果。
- 验收应包含 Excel 和 WPS 各自打开、编辑、另存再导入，并覆盖 Google 表格往返。样本包含中文、多行步骤、带逗号和引号的 JSON、001.02、公式样文本、空值和两种等级 4。另测 100/101 行边界、错误行整批回滚、重复确认、权限变化、跨页导出和已有 ID 回导。交付时记录实测软件版本、数据规模和耗时。
