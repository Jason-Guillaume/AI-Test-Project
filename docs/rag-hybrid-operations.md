# 混合检索配置和验证

## 数据库与部署

数据库需要 PostgreSQL 16 和 pgvector 扩展，执行迁移的数据库角色需要有安装扩展的权限。Compose 的 PostgreSQL 镜像包含扩展；已有数据库升级前应按现有运维流程备份。后端安装 `requirements.txt`，在 `backend` 目录执行：

```sh
alembic upgrade head
```

迁移 0097 创建无固定维度的向量列、索引代、项目配置和持久任务。现有项目默认未开启混合检索。知识解析 worker 同时消费索引任务；后台调用失败最多尝试三次，使用持久化退避时间，超时租约可由后续 worker 领取。索引目前逐片调用编码端点，不提供近似索引或吞吐保证。

## 管理入口

1. 在「统一模型中心」分别创建向量编码和重排资源，选择已注册的协议，填写**完整端点**、供应商模型标识和凭据。凭据沿用模型中心加密存储。向量协议使用 `model`、`input`，返回包含 `index`、`embedding` 的 `data` 数组；可配置文档和查询 `input_type`。重排协议使用 `model`、`query`、`documents`、`top_n`，返回 `results`，每项包含 `index` 和 `relevance_score`。为项目配置模型服务出站白名单，并在模型中心选择项目执行对应能力诊断。向量诊断需要填写预期维度。
2. 在「项目知识库 → 混合检索配置」选择向量模型修订，填写实际维度、距离、服务端模型/编码版本标记和可选输入模式，创建索引代。创建操作登记存量已就绪文档的回填任务；解析新版本时会在同一事务内登记任务。页面展示任务状态和向量数。
3. 回填完成并按业务样本评测后，点击「切换 / 回滚」。切换会在项目锁内检查所有当前可用文档的已就绪版本是否有该代向量。查询使用选定代的模型与向量，旧代保持追平供回滚。空库也可以切换，后续新增片段会排队。
4. 选择可选重排模型、候选窗口、阈值和超时并保存。清空重排模型即可关闭重排，修改重排不创建向量任务。BM25、RRF 和重排分数尺度不同；BM25 阈值仍由搜索请求提供，另有可选 RRF 和重排阈值。

更换 embedding 的模型、维度或输入编码规则时创建新代，完成回填与抽样评测后切换；回滚时选择旧代并切换。仅轮换凭据或调整超时，且模型、协议及端点不变时，可创建新模型连接修订，运行时沿用当前凭据，旧代不重编码。改变端点或模型标识请创建新索引代。请保留回滚代对应的模型资源和修订处于启用状态。

模型中心的“删除”会停用并归档资源，保留历史修订；管理员可在“已删除”视图恢复为停用状态。默认策略、备用策略或项目检索仍引用模型时须先解除引用。对于不再需要回滚的非当前索引代，可在项目知识库退役；退役会停止未完成任务，且该代不能再切换或回滚。当前索引代须先切换到其他代才能退役。

在 `backend` 目录可对已有代执行操作：

```sh
python -m scripts.knowledge_index status --generation-id <索引代ID>
python -m scripts.knowledge_index backfill --generation-id <索引代ID>
python -m scripts.knowledge_index retry --generation-id <索引代ID>
```

这些命令只登记或重置任务，实际编码由运行中的知识 worker 执行。`backfill` 幂等补齐缺失任务，`retry` 重置失败任务；页面也提供相应按钮。空查询和 `limit=0` 只做权限复核，不调用检索模型。模型不可用时回退 BM25，重排失败保留 RRF 排名。

## 本地合成对比

运行 `pytest -q -s app/knowledge/tests/test_indexing.py::test_synthetic_public_search_comparison`。下列为一次 SQLite、假编码和假重排运行：同一批 4 个合成问题，其中 3 个有答案、1 个无答案；P95 以 4 次样本的最大值估计，模型和网络延迟均未包含，不能用于容量规划或真实模型质量结论。

| 策略 | Recall@30 | Hit@8 | MRR | 无答案问题返回数（前 8） | P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.333 | 0.333 | 0.333 | 0 | 17.7 ms |
| 混合 | 1.000 | 1.000 | 1.000 | 8 | 22.8 ms |
| 混合 + 重排 | 1.000 | 1.000 | 1.000 | 8 | 13.9 ms |

假向量和重排刻意编码了标签；该测试用于检查管线，而非估计业务增益。无答案样本的向量路径仍返回候选，需用真实标注集评估阈值和拒答策略。

另一个单条合成样本单独比较 BM25 查询改写：泛化标题的 Hit@8 为 0，拼入包含目标错误码的需求后为 1；这与上表的向量增益分开测量，同样不能推断真实业务效果。
